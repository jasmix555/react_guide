<LearnBox>

- `if` の中で、`true` / `false` 以外の値がどう扱われるか
- 「偽」とみなされる 6 つの値（falsy）
- `0` や空文字が偽になる罠、文字列 `'0'` が真になる罠

</LearnBox>

## なぜこれが重要なのか {#why}

JavaScript の `if` は、`true` / `false` だけでなく、**あらゆる値**を「真っぽいか・偽っぽいか」で判断します。この「っぽさ」を **truthy（真っぽい）/ falsy（偽っぽい）** と呼びます。React で「値があるときだけ表示する」という書き方をするので、ここを外すと表示のバグに直結します。

まず、`if` の 1 行を部品に分けて名前を付けます。

```js
   if (値) { ... }
// ↑   ↑   ↑
// │   │   └─ 真のときに実行する中身
// │   └─ この値の「っぽさ」で真偽を判定（true/false でなくてよい）
// └─ もし〜なら
```

- **`if`** … 「もし〜なら」。中身を実行するかどうかの分岐
- **`(値)`** … ここに置いた値の **truthy / falsy** で判定する。`=== true` と比べているわけではない
- **`{ ... }`** … 値が truthy のときだけ実行される

## 偽っぽい値（falsy）は 6 つだけ {#falsy}

覚えるのは「**偽っぽい値**」の方です。これだけが `false` 扱いで、**それ以外は全部** `true` 扱いになります。falsy は次の 6 つです。

```js
false      // false そのもの
0          // 数値のゼロ
''         // 空の文字列（何も入っていない）
null       // 「何もない」を表す値
undefined  // 「まだ無い」を表す値
NaN        // 計算に失敗した数値（Not a Number）
```

この 6 つ以外は、たとえ `'0'`（文字のゼロ）でも `[]`（空の配列）でも `{}`（空のオブジェクト）でも、**全部 truthy（真っぽい）** です。ここが直感とずれる場所です。

<JsNote feature="truthy / falsy は「if の中でどう扱われるか」">

`if (値)` と書いたとき、その値が falsy なら「偽」、そうでなければ「真」として分岐します。`if (値 === true)` のように厳密に比べているわけではなく、「っぽさ」で判断している、と理解してください。

</JsNote>

## わざと壊す：0 は偽、でも '0' は真 {#break-zero}

一番ハマるのが、数値の `0` と文字列の `'0'` の違いです。コンソールで見比べます。

```js
if (0) console.log('入った')
// → 何も出ない（0 は falsy）

if ('0') console.log('入った')
// → 入った（'0' は文字列なので truthy）
```

数値の `0` は falsy なので `if` の中に入りません。でも、`'0'`（クォートで囲まれた文字のゼロ）は**中身のある文字列**なので truthy、`if` の中に入ります。「見た目はゼロなのに結果が逆」——これがよくある混乱のもとです。

同じく、**空文字 `''` は falsy** です。フォームの入力が空かどうかを `if (input)` で判定できますが、`0` を入力されたときに困る場面もあるので、意味を分かって使う必要があります。

<Callout type="warn">

「値があるはずなのに表示されない」ときは、その値が `0` や `''` や `null` になっていないかを疑ってください。とくに**個数や在庫が `0` のとき**、`if (count)` が偽になって表示が消える、という事故が起きます。

</Callout>

## 短絡評価との関係（予告） {#preview}

次のページで学ぶ `&&` は、この truthy / falsy を使って「左が真っぽいときだけ右を返す」という動きをします。React の「値があるときだけ表示する」書き方の土台になるので、まずここで「偽っぽいのは 6 つだけ」を固めておいてください。

```js
// → 出る（空配列は truthy！）

// → 出る（空オブジェクトも truthy！）
```

意外かもしれませんが、**空の配列も空のオブジェクトも truthy** です。falsy の 6 つに入っていないからです。「配列が空かどうか」を知りたいときは、`if (arr.length === 0)` のように**長さ**で判定します（`if (arr)` では空でも真になってしまいます）。

</Together>

## 書き方カタログ：判定の書き方 {#catalog}

「何を判定したいのか」で書き分けます。存在の有無は truthy 判定でよいですが、数量や「空かどうか」は意味で比べます。

```js
if (user) { }               // 存在するか（オブジェクト）→ truthy 判定でOK
if (name) { }               // 文字列が空でないか（'' は falsy）
if (count > 0) { }          // 数量は意味で比べる（0 を巻き込まない）
if (text.length > 0) { }    // 中身があるか → length で判定
if (items.length === 0) { } // 「空のとき」を明示的に
if (isOpen) { }             // 真偽値はそのまま
```

`if (count)` や `if (items)` のように truthy 任せにすると、`0` や空配列 `[]` で事故ります。数量・空判定は `> 0` や `.length` で**何を見たいか**を書きます。

## うちの標準 {#standard}

<Std
  decision="「存在するか」は truthy 判定でよいが、「数量」や「空かどうか」は意味で明示的に比べる"
  alt="null / undefined かどうかだけを見たいなら、後のページの ?? や == null を使うと、0 や '' を巻き込まずに判定できます。"
>

`if (user)`（ユーザーが居るか）は truthy 判定で自然です。一方 `if (count)`（個数）や `if (text)`（入力）は、`0` や `''` を巻き込むので、`count > 0`、`text.length > 0` のように**何を判定したいのか**を書きます。

</Std>

## うまくいかないとき {#trouble}

- **値があるのに表示されない** … その値が `0` `''` `null` `undefined` になっていないか確認します。
- **空のはずなのに「ある」扱いになる** … 空配列 `[]`・空オブジェクト `{}` は truthy です。`.length === 0` や中身で判定します。
