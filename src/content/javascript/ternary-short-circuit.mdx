<LearnBox>

- `条件 ? A : B`（三項演算子）で「どちらかを選ぶ」
- `&&` で「真のときだけ返す」、`||` で「偽なら代わりを返す」
- `0 && …` が `0` を返す罠（React の表示バグの正体）

</LearnBox>

## なぜ if ではなくこれを使うのか {#why}

React では、JSX の中（`{ }` の中）に `if` 文を書けません。代わりに「**値を返す**」形で条件分岐を書く必要があります。そのための道具が、**三項演算子 `? :`** と、**短絡評価 `&&` / `||`** です。まず素の JavaScript で仕組みを押さえます。

## 三項演算子：どちらかを選ぶ {#ternary}

`条件 ? A : B` は、「条件が真なら `A`、偽なら `B` を返す」式です。`if / else` を 1 行にしたものだと思ってください。

```js
const stock = 0
const label = stock > 0 ? '在庫あり' : '在庫なし'

console.log(label) // 在庫なし
```

`stock > 0` が偽なので、`:` の後ろの `'在庫なし'` が選ばれました。`?` の前が条件、`?` と `:` の間が「真のとき」、`:` の後が「偽のとき」です。

この 1 行を、部品に分けて名前を付けます。

```js
   条件 ? A : B
// ↑    ↑   ↑
// │    │   └─ 偽のときに返す値（: の後ろ）
// │    └─ 真のときに返す値（? と : の間）
// └─ 判定する条件。true / false になる式
```

- **`条件`** … `true` / `false` になる式（`stock > 0` など）
- **`? A`** … 条件が**真**のときに返す値
- **`: B`** … 条件が**偽**のときに返す値
- 全体で 1 つの**値を返す式**。変数や JSX の `{ }` の中に置ける

<JsNote feature="? : は式（値を返す）">

`if` 文は「処理」で、値を返しません。三項演算子 `? :` は「**式**」で、結果の値を返します。だから `const label = ... ? ... : ...` のように、変数に入れたり、React の `{ }` の中に書いたりできます。

</JsNote>

## && ：真のときだけ返す {#and}

`A && B` は、「`A` が真っぽいなら `B` を返し、そうでなければ `A`（偽の値）を返す」という動きをします。React では「条件が真のときだけ表示する」に使います。

```js
const isMember = true
const message = isMember && 'ようこそ、会員さま'

console.log(message) // ようこそ、会員さま
```

`isMember` が真なので、右の文字列が返りました。もし `isMember` が `false` なら、`message` は `false` になり、React では**何も表示されません**（`false` は画面に出ない）。この「真のときだけ出す」が `&&` の使いどころです。

`&&` も、部品に分けて名前を付けておきます。

```js
   A && B
// ↑ ↑  ↑
// │ │  └─ A が真っぽいときだけ返る値
// │ └─ && は「左が真っぽければ右を返す」
// └─ 左の値。falsy ならこれがそのまま返る（0 の罠）
```

- **`A`（左）** … 先に truthy / falsy を判定する値。falsy なら**これがそのまま返る**
- **`&&`** … 「左が真っぽいときだけ右を返す」演算子
- **`B`（右）** … 左が真のときに返る値（React では表示したい JSX）
- 左が `0` になる数値だと `0` が返って画面に漏れる → 左は `count > 0` のような真偽値に

## || ：偽なら代わりを返す {#or}

`A || B` は逆で、「`A` が真っぽければ `A`、偽っぽければ `B`（代わり）を返す」動きです。「値が無ければ既定値」に使えます。

```js
const nickname = ''
const display = nickname || '名無しさん'

console.log(display) // 名無しさん（'' は falsy なので代わりが返る）
```

`nickname` が空文字（falsy）なので、代わりの `'名無しさん'` が返りました。

## わざと壊す：0 && で 0 が返る {#break-zero-and}

`&&` の一番有名な落とし穴が、**左が `0` のとき**です。前のページで「`0` は falsy」と学びました。それがここで牙をむきます。

```js
const count = 0
const result = count && '商品あり'

console.log(result) // 0   ← '' でも false でもなく、数値の 0
```

`count` が `0`（falsy）なので、`&&` は右を見ずに**左の `0` をそのまま返し**ました。ここまでは仕様どおりです。問題はこの後です。React で `{count && <p>商品あり</p>}` と書くと、`count` が `0` のとき、画面に**「0」という数字がそのまま表示**されてしまいます。「何も出ないはず」が「0 が出る」になる、有名なバグです。

防ぎ方は、**左を必ず true / false にする**ことです。

```js
const result = count > 0 && '商品あり' // 左を count > 0（true/false）にする
```

`count > 0` は `false`（真偽値）になるので、`&&` は `false` を返し、React では何も表示されません。**`&&` の左には、`0` になりうる数値をそのまま置かない**——これが鉄則です（React での表示は後のパートで詳しくやります）。

<Callout type="warn">

`{something && <JSX/>}` で「0 が表示される」ときは、`&&` の左が `0` になる数値（`length` や個数）になっていないかを疑ってください。左を `> 0` などの真偽値に直せば消えます。

</Callout>

## 書き方カタログ：条件で出し分けるいろいろ {#catalog}

「二択なら `? :`」「片方だけ出すなら `&&`」「無ければ代わりなら `||`」と使い分けます。

```tsx
const label = stock > 0 ? '在庫あり' : '在庫なし' // 二択の文字列
const badge = isSale ? <Tag>SALE</Tag> : null    // 要素を出す/出さない（無しは null）
const fee = isFree ? 0 : 300                      // 数値でもよい
const msg = isMember && 'ようこそ'               // 片方だけ（&&）
const name = nickname || '名無し'                // 無ければ代わり（||）
const view = a ? '甲' : b ? '乙' : '丙'          // ネストは読みにくい → 変数に切り出す
```

3 択以上を三項演算子で入れ子にすると一気に読めなくなります。その場合は、分岐を先に変数へ組み立ててから JSX に差し込みます。

## うちの標準 {#standard}

<Std
  decision="二択は三項演算子、片方だけ出すなら && を使い、&& の左は必ず真偽値にする"
  alt="分岐が3つ以上に増えたら、JSX の外で変数に組み立ててから差し込むほうが読みやすくなります。ネストした三項演算子は避けます。"
>

「A か B か」は `? :`、「あるときだけ」は `&&`。`&&` の左が数値になるときは `count > 0 &&` のように真偽値へ直します。三項演算子を入れ子にすると一気に読めなくなるので、その場合は分岐を変数に切り出します。

</Std>

## うまくいかないとき {#trouble}

- **画面に `0` が出る** … `&&` の左が `0` になる数値です。左を `> 0` などの真偽値にします。
- **三項演算子が読めない/エラー** … `?` と `:` が対になっているか、入れ子にしすぎていないかを確認します。入れ子なら変数に分けます。
