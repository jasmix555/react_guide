<LearnBox>

- 設定値をコードに直書きせず `.env` に分ける理由
- `VITE_` で始まる名前だけが画面から読める仕組み
- `import.meta.env.VITE_XXX` での読み方と、`.env` に秘密を置いてはいけない理由

</LearnBox>

## なぜ設定値をファイルに分けるのか {#why}

「サイト名」「API の URL」のような**設定値**は、コードのあちこちに直接書くと、変えたいときに探し回ることになります。また、開発中と本番で値を変えたい（テスト用 URL と本番用 URL など）こともあります。

そこで、こうした値を **`.env`（環境変数ファイル）** という 1 か所にまとめ、コードからは名前で読み出します。Vite にはこの仕組みが最初から入っているので、ライブラリは要りません。

## .env に書いて VITE_ で読み出す {#basic}

プロジェクトの一番上（`package.json` と同じ場所）に、`.env` というファイルを作ります。中身は「名前＝値」を 1 行ずつ書くだけです。

```bash title=".env（新規作成）"
VITE_SHOP_NAME=みんなの商品一覧
```

コードからは、`import.meta.env` に続けて名前を書いて読み出します。

```ts title="src/App.tsx"
const shopName = import.meta.env.VITE_SHOP_NAME
console.log(shopName) // みんなの商品一覧
```

<Callout type="warn">

`.env` を作ったり書き換えたりしたら、**開発サーバー（`npm run dev`）を一度止めて起動し直してください**。`.env` は起動時に読み込まれるので、動かしたまま編集しても反映されません。「値が変わらない」ときの原因の多くはこれです。

</Callout>

## わざと壊す：VITE_ を付け忘れる {#break-prefix}

ここが一番ハマる仕様です。Vite は、**`VITE_` で始まる名前しか画面（ブラウザ側のコード）に渡しません**。試しに、プレフィックス無しの名前を置いてみます。

```bash title=".env"
SHOP_NAME=みんなの商品一覧      # VITE_ が付いていない
VITE_SHOP_NAME=みんなの商品一覧  # こちらは付いている
```

```ts
console.log(import.meta.env.SHOP_NAME)      // undefined ← 渡されない
console.log(import.meta.env.VITE_SHOP_NAME) // みんなの商品一覧
```

`SHOP_NAME` は `undefined`。`VITE_` が付いていないので、ブラウザ側には**わざと渡されていない**のです。これはバグではなく、次に説明する**安全のための仕様**です。「`.env` に書いたのに `undefined`」のときは、まず `VITE_` の付け忘れを疑ってください。

## なぜ VITE_ だけなのか——秘密を置かない {#security}

「なぜ全部渡してくれないの？」の答えが、このページで一番大事なところです。**ブラウザに届いたコードは、誰でも中身を見られます**。あなたの JavaScript は、利用者の PC にダウンロードされて動くからです。

つまり、`VITE_` を付けて画面に渡した値は、**世界中に公開したのと同じ**です。だから Vite は「`VITE_` を付けたものだけ渡す＝**公開してよいと明示したものだけ**渡す」という設計にして、うっかり秘密が漏れるのを防いでいます。

<Callout type="warn">

**API の秘密鍵・パスワード・データベースの接続情報などを、`VITE_` を付けて `.env` に置いてはいけません。** それらは画面に渡った時点で丸見えになります。秘密の情報は、ブラウザではなくサーバー側で扱うものです（このガイドの範囲を超えるので、必要になったら別途学びます）。`.env` に置いてよいのは「公開されても困らない値」だけです。

</Callout>

## .env はコミットしない {#gitignore}

`.env` には環境ごとの値が入るため、**Git にはコミットしない**のが基本です（`create vite` の `.gitignore` に最初から `.env` が入っています）。代わりに、「どんな名前が必要か」を示す見本として **`.env.example`** を、値を空にして共有することがよくあります。

```bash title=".env.example（値は空・これは共有する）"
VITE_SHOP_NAME=
```

こうすると、他の人は「`VITE_SHOP_NAME` を用意すればいいんだな」と分かり、実際の値は各自の `.env` に書く、という形にできます。

<Together
  task=".env に VITE_MAX_ITEMS=8 を追加して、import.meta.env.VITE_MAX_ITEMS をコンソールに出してみてください。うまく出たら、VITE_ を外した MAX_ITEMS=8 でも試して、違いを見ましょう。（.env を変えたら dev サーバーを再起動）"
  hint="VITE_ 付きは読めて、VITE_ 無しは undefined になります。"
>

```bash title=".env"
VITE_MAX_ITEMS=8
MAX_ITEMS=8
```

```ts
console.log(import.meta.env.VITE_MAX_ITEMS) // '8'（VITE_ 付きは読める）
console.log(import.meta.env.MAX_ITEMS)      // undefined（VITE_ 無しは渡らない）
```

`VITE_` が付いた `VITE_MAX_ITEMS` だけが画面に渡り、無印の `MAX_ITEMS` は `undefined` です。ちなみに読み出した値は文字列（`'8'`）なので、数値として使いたいときは `Number(...)` で変換します。`.env` を編集したら dev サーバーの再起動を忘れずに。

</Together>

## うちの標準 {#standard}

<Std
  decision="設定値は .env にまとめ、画面から使う値だけ VITE_ を付ける。秘密の情報は絶対に置かない。.env はコミットせず .env.example を共有する"
  alt="値が 1 つしかなく、公開前提の固定値なら、無理に .env にせずコードの定数にしても構いません。環境で変えたい・数が増える・見本を共有したいときに .env が活きます。"
>

`.env` に置くのは「公開されても困らない値」だけ。`VITE_` を付けたものは全世界に見えると考えます。秘密鍵やパスワードはブラウザに渡さない。`.env` は各自のもの（コミットしない）で、必要な名前は `.env.example` で共有します。

</Std>

## うまくいかないとき {#trouble}

- **`.env` に書いたのに `undefined`** … 名前に `VITE_` が付いているか、`.env` を保存後に dev サーバーを再起動したかを確認します。
- **値が文字列で扱いにくい** … `import.meta.env.VITE_XXX` は常に文字列です。数値は `Number(...)`、真偽は自分で判定して使います。
- **`.env` を間違えてコミットした** … 秘密が入っていたら、その値は無効化（作り直し）が必要です。以後は `.gitignore` に `.env` があるか確認します。
