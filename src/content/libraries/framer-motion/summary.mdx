## このパートの総復習 {#recap}

一覧に「気持ちよさ」を足しました。要点を並べます。

- **motion の基本** … `<motion.div>` に `initial`（最初）→ `animate`（目指す状態）→ `transition`（動き方）。UI は `spring` が自然。
- **ホバー・タップ** … `whileHover` / `whileTap` で操作に反応。控えめ（数%）に。
- **reduced-motion** … `useReducedMotion` で配慮。**動きだけ消し、情報は残す**。
- **スクロール・stagger** … `whileInView`（見えたら・`once`）、`staggerChildren` ＋ `variants`（少しずつ）。
- **出入り** … `AnimatePresence` ＋ `exit` ＋ 固有の `key`。消えるときも滑らかに。

そして全体を貫く原則は 1 つ、**「動きには理由を持たせる」**。注目・状態変化・操作への反応。なんとなくで動かさない、が完成度の分かれ目です。

## 次に読むと良いもの {#next}

これで **Framer Motion** は一通りです。`initial`→`animate` の基本から、ホバー・reduced-motion・stagger・出入りまで、「気持ちよく動く」UI を自分で付けられるようになりました。

この先は、同じ **ライブラリ編** の他のパートへ。**GSAP**（タイムラインやスクロール連動の凝った演出）、**Swiper**（スライダー / カルーセル）などを、順次このタブに追加していきます。作りたい UI が先にあるなら、**[レシピ](/recipes/modal)** から逆引きするのも近道です。

<SummaryBox>

- `initial` → `animate` → `transition` が基本。ホバーは `whileHover`/`whileTap`
- reduced-motion は必須配慮（動きだけ消す）。stagger は `variants`、出入りは `AnimatePresence`
- 動きには理由を。次は GSAP・Swiper など、必要なライブラリを引きながら
</SummaryBox>
