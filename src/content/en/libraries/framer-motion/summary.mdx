## Recap of this part {#recap}

We added "that satisfying feel" to a list. Here are the key points.

- **Motion basics** … on a `<motion.div>`, `initial` (start) → `animate` (target state) → `transition` (how it moves). For UI, `spring` feels natural.
- **Hover & tap** … react to input with `whileHover` / `whileTap`. Keep it restrained (a few percent).
- **reduced-motion** … show care with `useReducedMotion`. **Remove only the motion; keep the information.**
- **Scroll & stagger** … `whileInView` (fire when visible, with `once`), and `staggerChildren` + `variants` (a little at a time).
- **Enter/exit** … `AnimatePresence` + `exit` + a unique `key`. Smooth on the way out too.

And running through all of it is one principle: **"give motion a reason."** Draw attention, show a state change, react to input. Not moving things "just because" is what separates a polished result from an unpolished one.
