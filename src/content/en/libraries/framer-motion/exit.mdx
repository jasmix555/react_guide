## "Disappearing" is the hard part {#why}

`initial` / `animate` were the motion for "when something appears." But **animating something as it disappears** doesn't work out of the box. Here's why: when you remove an element from a list, React **removes it from the DOM immediately**, so there's **no moment** to show a "fading out" animation.

That's where **`AnimatePresence`** comes in. It's the piece that **keeps a disappearing element in the DOM until its animation finishes**.

## AnimatePresence and exit {#animate-presence}

Wrap the elements that might disappear in `<AnimatePresence>`, and give each element an **`exit`** (the state it heads toward as it disappears).

```tsx
import { AnimatePresence, motion } from 'motion/react'

<AnimatePresence>
  {items.map((item) => (
    <motion.li
      key={item.id} // ← this is critical (explained below)
      initial={{ opacity: 0, height: 0 }} // when appearing
      animate={{ opacity: 1, height: 'auto' }} // while shown
      exit={{ opacity: 0, height: 0 }} // when disappearing
      transition={{ duration: 0.25 }}
    >
      {item.name}
    </motion.li>
  ))}
</AnimatePresence>
```

- **`AnimatePresence`** … keeps a disappearing element around until its `exit` animation finishes.
- **`exit`** … the state to head toward when disappearing (transparent, height 0, so it closes smoothly).

Now when you remove one item from `items`, that element **doesn't vanish right away — it shows its `exit` motion first**, then goes away.

## key is everything {#key}

What lets `AnimatePresence` tell "which one disappeared" is the **`key`** (same idea as [keys in lists](/guide/components/rendering-lists), but even more important here). If the `key` isn't correctly **unique per element**, a different element may look like it disappeared, or `exit` may not run at all.

<Callout type="warn" title="Don't use index as key">

Avoid `key={index}`. Removing an item shifts the numbers, and `AnimatePresence` mistakes elements for different ones. Use a **unique value tied to the element itself**, like `key={item.id}`.

</Callout>

## When it doesn't work {#trouble}

- **Removal snaps out (exit has no effect)** … check that it's wrapped in `<AnimatePresence>` and each element has a `key` and an `exit`.
- **It disappears but moves oddly** … check that you aren't using an index as the `key`. Use a unique value like `item.id`.
- **The height animation is jerky** … add `overflow: hidden` to the element (so its contents don't spill out at height 0).
