## Full review of this part {#recap}

We've touched the heart of React from end to end. Here are the key points.

- **How re-rendering works** … Changing a plain variable doesn't change the screen. React re-draws **only when you update state**.
- **useState** … `const [count, setCount] = useState(0)`. You read `count` and change it with `setCount`.
- **Updating with events** … `onClick={() => setX(...)}`. Flip ON/OFF with `!value`. Calling it directly gives `Too many re-renders`.
- **Immutable updates** … For arrays, `[...prev, x]` / `filter`; for objects, `{ ...prev, thing to change }`. Mutating the original means no re-render (references and copies, Part 2).
- **The functional form** … Updates determined by the previous value use `set(prev => ...)`. It won't drop updates even under rapid updates.
- **useEffect** … Side effects run after rendering. The dependency array decides "when it runs", and `return` handles cleanup.

Behind everything that "makes the screen change" there's always state — this way of seeing things will keep paying off from here on.

## Capstone: add favorites to ProductCard {#project}

Let's breathe life into the capstone `ProductCard` with what's in this part. **Each card will hold state for "whether it's a favorite"**, toggled with a button.

```tsx title="src/components/ProductCard/ProductCard.tsx (adding favorites)"
import { useState } from 'react'

interface ProductCardProps {
  name: string
  price: number
}

export function ProductCard({ name, price }: ProductCardProps) {
  const [favorite, setFavorite] = useState(false)

  return (
    <article>
      <h3>{name}</h3>
      <p>{price.toLocaleString()} yen</p>
      <button type="button" onClick={() => setFavorite((prev) => !prev)}>
        {favorite ? '♥ Favorited' : '♡ Favorite'}
      </button>
    </article>
  )
}
```

Each card in the list holds its own independent `favorite` state. Pressing one heart doesn't change the other cards (because state is separate per component). For now, get "press to toggle" working with this.

<Callout type="note">

"I want to see the products I favorited on a different screen (a favorites list) too" — once you get there, you'll need to **lift the state up to a parent and share it** rather than keeping it in each card (**lifting state up**). We'll cover this properly when we build multiple screens. For now, "each card holds its own state" is enough.

</Callout>

</Exercise>

What does the `[]` (dependency array) in `useEffect(fn, [])` decide? And what happens in an effect using `setInterval` if you don't write `return () => ...`?
