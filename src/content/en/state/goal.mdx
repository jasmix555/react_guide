## Why state is the core of React {#why}

As you learn React, `useState` is a **central topic you can't get around**. That's because almost all of an app's "movement" is made of state.

- The cart count goes up → hold the count in state
- A modal opens and closes → hold whether it's open in state
- Search narrows the list → hold the search term in state
- A favorite toggles → hold whether it's a favorite in state

**Behind anything where "the screen changes," there is always state**—you can safely assume so. That's why you should take this part slowly, working through it by hand. When something is unclear, the fastest route is to actually touch the demo and compare it with the code.

## How this part is structured {#roadmap}

One page per hook, each one a complete reference you can come back to.

1. **useState** — why "just a variable" won't do, then form inputs, toggles, lists, object state, and the updater form.
2. **useEffect** — syncing with the outside world: listeners, observers, fetching, and cleanup.
3. **useRef** — values that don't redraw the screen (focusing an input, holding a timer id).
4. **useContext** — letting a deep component read a value without props being passed through everything in between.
5. **useMemo** — caching a calculated value so it is not redone on every update.
6. **useCallback** — keeping a function the same function, so `memo()` and dependency arrays work.

Each page comes with a **live demo** and **practice**. Don't just read—always write it out yourself and run it.
