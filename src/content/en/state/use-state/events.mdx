## Break down the onClick syntax {#anatomy}

We combine the events from Part 3 (`onClick`) with the state from this part. First, let's break down the one line we're about to write.

```tsx
onClick={() => setFavorite(!favorite)}
//       ↑     ↑           ↑
//       │     │           └─ the opposite of the current value (true ⇄ false)
//       │     └─ the function that updates state. Call it and a re-render happens
//       └─ wrap it in () =>. It runs only once clicked
```

- **Wrap it in `() =>`** … you pass "a function to run when clicked." Don't add `()` to run it immediately (we'll see the trap later).
- **`setFavorite(...)`** … the state updater function. Call it and it re-renders.
- **`!favorite`** … the opposite of the current value (`!` is the "flip it" from [how to read the symbols](/guide/javascript/symbols)). `true` becomes `false`, `false` becomes `true`.

## Write the favorite button in full {#build}

Create a new file `src/components/FavoriteButton/FavoriteButton.tsx` and paste in **this entire file**.

```tsx title="src/components/FavoriteButton/FavoriteButton.tsx (new file, full source)"
import { useState } from 'react'

export function FavoriteButton() {
  const [favorite, setFavorite] = useState(false)

  return (
    <button type="button" onClick={() => setFavorite(!favorite)}>
      {favorite ? '♥ Favorited' : '♡ Add to favorites'}
    </button>
  )
}
```

We hold "whether it's a favorite" as boolean state (`favorite`) and flip it on each click.

## What happens when you save {#result}

Press the button and `setFavorite(!favorite)` is called, so `favorite` toggles between `true` and `false`. When state changes, it re-renders, and the `favorite ? ... : ...` ternary picks the new display (the heart and the text) all over again. This is the basic shape of how React works: "click → update state → re-render."

## Break it on purpose: write setState directly in onClick {#break-loop}

The "add `()` to run it immediately" trap from Part 3 turns into a **much more dramatic symptom** with state. Without wrapping it in an arrow function, let's write `setFavorite` directly.

```tsx
<button type="button" onClick={setFavorite(!favorite)}>
```

The moment you save, the screen freezes and a flood of errors appears in the console.

```
Error: Too many re-renders. React limits the number of renders
to prevent an infinite loop.
```

It means "**too many re-renders. React stopped it to prevent an infinite loop.**" `onClick={setFavorite(!favorite)}` **runs `setFavorite` during rendering** without waiting for a click. → state changes → re-render → `setFavorite` runs again → re-render again… **repeating forever**. To prevent it, always wrap it in an arrow function.

```tsx
<button type="button" onClick={() => setFavorite(!favorite)}>
```

Wrap it in `() =>` and `setFavorite` runs only when clicked. **When you see `Too many re-renders`, the first thing to suspect is whether you're calling `setState` directly inside `onClick`.**

## Writing catalog: event handlers {#catalog}

There are a few common forms for passing an event. Learning them all at once saves you from second-guessing.

```tsx
// ① pass a function you prepared (no arguments)
<button onClick={handleClick}>Submit</button>

// ② write it inline (no arguments)
<button onClick={() => setOpen(true)}>Open</button>

// ③ call with arguments → wrap in an arrow function (don't add () directly)
<button onClick={() => buy(product)}>Buy</button>

// ④ use the event object e (to read an input's value, etc.)
<input onChange={(e) => setName(e.target.value)} />
```

① passes "just the function's name." ② and ③ "create a function on the spot" and pass it. ④ is for input fields and such, using information about the event that happened (`e.target.value` = the text typed). What they all share: "**pass a function**. Don't add `()` to run it immediately." Follow just that and you won't have accidents.

  hint="const [open, setOpen] = useState(false), setOpen(!open) in onClick, and {open && <p>description</p>} to show or hide."

```tsx title="src/components/Detail/Detail.tsx (new file, full source)"
import { useState } from 'react'

export function Detail() {
  const [open, setOpen] = useState(false)

  return (
    <div>
      <button type="button" onClick={() => setOpen(!open)}>
        {open ? 'Close' : 'Show details'}
      </button>
      {open && <p>The product description goes here.</p>}
    </div>
  )
}
```

We flip `open` with `!open` and use `{open && <p>...</p>}` to "show the description only when `open` is `true`" (the [conditional display](/guide/components/conditional) from Part 3). Open/close, show/hide, and ON/OFF can all be built with this "flip a boolean state."

## Our standard {#standard}

<Std
  decision="For ON/OFF, open/close, and show/hide, flip a boolean state with !value. Always wrap the event in an arrow function"
  alt="The functional form setFavorite(prev => !prev), which you'll learn on the next page, is safer when toggling rapidly in quick succession. For now, grasp the mechanism with the !favorite form."
>

For "toggling," flipping a boolean state is the standard. `onClick={() => setX(!x)}`. Don't forget to wrap it in `() =>`—forget it and you get an infinite loop with `Too many re-renders`.

</Std>

## When things go wrong {#trouble}

- **`Too many re-renders`** … You're calling `setState` during rendering, like `onClick={setX(...)}`. Fix it to `onClick={() => setX(...)}`.
- **Clicking doesn't toggle it** … Check whether you're calling `setState`, and whether you're flipping with `!value`.
- **It shows for an instant then disappears / the screen freezes** … This can be an early symptom of an infinite loop. First look at how you wrote `onClick`.
