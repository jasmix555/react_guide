## Sometimes you need to touch the real element {#why}

With `useState` you say "what to show" and React draws it. But some jobs can't be expressed that way — **focus this input, scroll to this element, measure this box's height**. For these you need **the actual DOM element on screen**, and the way to hold on to it is **`useRef`**.

`useRef` also has a second job: **holding a value that survives re-renders but doesn't cause one** (a timer id, a "have I run this already?" flag). Same tool, two uses.

<Callout type="analogy">

`useState` is a whiteboard on the wall — write on it and everyone in the room looks up. `useRef` is a sticky note in your pocket. It's still there next time you look, but writing on it doesn't make anyone turn around.

</Callout>

## Break down the useRef syntax {#anatomy}

```tsx
const inputRef = useRef<HTMLInputElement>(null)
//    ↑                 ↑                  ↑
//    │                 │                  └─ ② the starting value (null until React attaches it)
//    │                 └─ ① the type of element it will point at
//    └─ a box with one drawer: read and write it as inputRef.current

<input ref={inputRef} />
//     ↑ ③ hand the box to React, and it puts the real element into .current

inputRef.current?.focus() // ④ use it (?. because it is null before it is attached)
```

- **① The type** … `HTMLInputElement` for an `<input>`, `HTMLDivElement` for a `<div>`. Your editor then knows which methods exist.
- **② The starting value `null`** … The element doesn't exist yet on the first render. It's filled in after the screen is drawn.
- **③ `ref={inputRef}`** … The one place you connect them. React writes the real element into `.current`.
- **④ `.current`** … Always through `.current`. And always with `?.`, because it can be `null`.

## Write a focus button in full {#build}

Create `src/components/SearchBox/SearchBox.tsx` and paste in **this full file**. Press the button and the cursor jumps into the input.

```tsx title="src/components/SearchBox/SearchBox.tsx (new file, full)"
import { useRef } from 'react'

export function SearchBox() {
  const inputRef = useRef<HTMLInputElement>(null)

  return (
    <div>
      <input ref={inputRef} placeholder="Search" />
      <button type="button" onClick={() => inputRef.current?.focus()}>
        Focus the input
      </button>
    </div>
  )
}
```

## What happens when you save {#result}

Click the button and the input gets the cursor. Notice that **nothing was redrawn** — no state changed. You reached out and told the real element "focus yourself", which is exactly what a ref is for.

## Updating a ref does not redraw the screen {#no-render}

That's the whole difference, and it's worth staring at.

```tsx
const count = useRef(0)

function handleClick() {
  count.current += 1 // the value really does go up...
  console.log(count.current) // 1, 2, 3 — the console proves it
}

return <p>{count.current}</p> // ...but this stays 0 on screen
```

The number in `count.current` genuinely increases. The screen just never hears about it, because **only a state update tells React to redraw**. In the demo, the ref number sits still until you press `state +1` — and then it jumps to the value it had been at all along.

| | `useState` | `useRef` |
| --- | --- | --- |
| Changing it redraws the screen | **Yes** | **No** |
| How you update it | `setCount(1)` | `ref.current = 1` |
| Survives re-renders | Yes | Yes |
| Use it for | anything you display | DOM elements, timer ids, flags |

**Rule of thumb: if it appears on screen, it's state. If it doesn't, a ref is fine.**

## Holding a value: a timer you can stop {#value}

The second job, in practice. A stopwatch has to remember the id `setInterval` gave it, so `clearInterval` can stop it later. That id is never displayed, so it doesn't belong in state.

```tsx
const timerRef = useRef<number | null>(null)

function start() {
  if (timerRef.current !== null) return // already running
  timerRef.current = window.setInterval(() => setSeconds((s) => s + 1), 1000)
}

function stop() {
  if (timerRef.current === null) return
  clearInterval(timerRef.current)
  timerRef.current = null
}
```

`seconds` is state (it's on screen). The timer id is a ref (it isn't). Putting the id in state would redraw the whole component for a number nobody ever sees.

## Break it on purpose: display a ref {#break-display}

Take the demo's right panel and try to make it work with a ref alone.

```tsx
const count = useRef(0)

return (
  <button type="button" onClick={() => { count.current += 1 }}>
    Clicked {count.current} times
  </button>
)
```

Save and click. The label **stays at 0 forever**. No error, no warning — the worst kind of bug, because nothing tells you anything is wrong. The fix is not a better ref; it's **`useState`**, because this number is on screen.

## Cheat sheet: the 4 shapes you will actually use {#catalog}

```tsx
// ① focus an element
const inputRef = useRef<HTMLInputElement>(null)
inputRef.current?.focus()

// ② scroll to an element
const topRef = useRef<HTMLDivElement>(null)
topRef.current?.scrollIntoView({ behavior: 'smooth' })

// ③ hold a timer id so you can stop it
const timerRef = useRef<number | null>(null)
timerRef.current = window.setInterval(tick, 1000)

// ④ measure an element (inside useEffect, after it is drawn)
const boxRef = useRef<HTMLDivElement>(null)
useEffect(() => {
  console.log(boxRef.current?.getBoundingClientRect().height)
}, [])
```

Shapes ①–③ show up all over [the recipes](/recipes/modal) — modals focus their close button, "back to top" scrolls, toasts hold a timer id.

const closeRef = useRef<HTMLButtonElement>(null)

Touching the DOM is a side effect, so it goes in `useEffect` — and it has to run **after** the button is drawn, which is exactly when an effect runs. The dependency array `[open]` re-runs it every time the modal opens.

## Our standard {#standard}

<Std
  decision="Use useRef for DOM elements and for values that are never displayed. Everything that appears on screen stays in useState"
  alt="If you find yourself wanting a ref so a value won't cause a re-render, but you do display it, that's a sign the value should be state and something else needs fixing. Reach for a ref only when the value is genuinely invisible."
>

`useRef` is a box you reach through `.current`. `ref={...}` on an element to touch the DOM (focus, scroll, measure), or a plain `useRef(value)` to remember something across renders (timer ids, flags). Writing to `.current` never redraws — that's the point, and also the trap.

</Std>

## When things go wrong {#trouble}

- **`Cannot read properties of null (reading 'focus')`** … You read `.current` before React attached the element. Use `?.`, and do it in an event handler or `useEffect`, not during render.
- **The number doesn't change on screen** … It's in a ref. Move it to `useState`.
- **`Property 'focus' does not exist on type ...`** … The type argument is wrong. Match the element: `useRef<HTMLInputElement>(null)` for an `<input>`.
