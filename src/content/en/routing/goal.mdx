## Why you need routing {#why}

An LP was self-contained in a single `index.html`. If you needed another page, you'd **split it into a separate file** like `about.html`. React's SPA (Single Page Application) works differently. **The HTML stays as a single file**, and JavaScript rewrites the contents to "look like a different page."

That's where the following things become tricky:

- You want the "product detail page" to have its **own direct URL** (so you can share a link).
- You want the browser's **back and forward** buttons to work.
- You want to **switch what's shown** based on "which page you're on right now."

Doing this by hand is a lot of work. **react-router** is a tool that maps "a URL and the screen to show for that URL." When the URL changes, the screen changes, and following a link doesn't trigger a reload.

## How this part is structured {#roadmap}

1. **Set up the router** — register "this screen for this URL."
2. **Navigate with Link** — use `<Link>` (no reload) instead of `<a>`.
3. **URL params** — use `:id` in `/product/:id` for a per-product detail page.
4. **Shared layout** — put the nav shared by every page in one place with `<Outlet>`.
5. **Navigate from code** — move around from a button and such with `useNavigate`.
6. **Capstone** — build the three pages: list → detail → favorites.

Each page comes with **full code** and practice. Follow along in `my-shop`, actually switching URLs as you go.
