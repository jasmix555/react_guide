## Don't build a page per product {#why}

Just because there are 12 products doesn't mean you should create 12 detail-page files. You build **a single template**. You make only part of the URL (the product's id) a variable, and show "the product with that id."

- `/product/p01` → the detail for p01
- `/product/p05` → the detail for p05

Both are handled by **the same `ProductDetailPage`**; only the id part of the URL differs.

## Receive a param with :id {#param}

In the route registration, write the part you want to be a variable as **`:name`**.

```tsx
{ path: '/product/:id', element: <ProductDetailPage /> }
//                ↑
//                └─ the part starting with : is a "variable". Both /product/p01 and /product/p05 match
```

`:id` means "some single value goes here." Both `/product/p01` and `/product/xyz` match this one route.

## Pull it out with useParams {#useparams}

The id in the URL is pulled out with `useParams`. You receive it with the **same name** as the `:id` in the route definition.

```tsx
import { useParams } from 'react-router-dom'

function ProductDetailPage() {
  const { id } = useParams()
  // if /product/p01 is open, id is 'p01'
}
```

```tsx
const { id } = useParams()
//      ↑            ↑
//      │            └─ pulls out the :id part of the URL
//      └─ receive it with the same name as :id in the route definition
```

## Look up the product and display it {#find}

Once you know the id, you look up that product from `products` with `find`. What matters here is handling the **not-found case** (say, someone typed an id that doesn't exist).

```tsx title="src/pages/ProductDetailPage.tsx (full file)"
import { useParams } from 'react-router-dom'

import products from '../data/products.json'

export function ProductDetailPage() {
  const { id } = useParams()
  const product = products.find((p) => p.id === id)

  if (!product) {
    return <p>Product not found.</p>
  }

  return (
    <article>
      <h1>{product.name}</h1>
      <p>{product.price.toLocaleString()} yen</p>
      <p>Category: {product.category}</p>
    </article>
  )
}
```

With `if (!product) return ...`, you bail out early when there's nothing. Thanks to this one line, you can write `product.name` safely (it's the same idea as [narrowing a union](/guide/typescript/union-literal)).

<JsNote feature="the value from useParams is string | undefined">

The `id` you pull out with `useParams` is `string` or `undefined` (because that part might not be in the URL). The result of `find` is also "the product found, or `undefined`." That's why you need the `if (!product)` check. Skip it and the type complains that "`product` might be `undefined`" at `product.name`.

</JsNote>

## Break it on purpose: don't handle the not-found case {#break}

Let's remove `if (!product)`.

```tsx title="Break it on purpose: remove the check"
const product = products.find((p) => p.id === id)
return <h1>{product.name}</h1> // ← product might be undefined
```

A red squiggle appears under `product.name`, with this message.

```
'product' is possibly 'undefined'.
```

"`product` might be `undefined`." That's because if an id that doesn't exist comes in, `find` returns `undefined`. Put `if (!product) return ...` back, and from there on it's narrowed to "the product found," so you can safely write `product.name`.

## When things don't work {#trouble}

- **The `useParams` name doesn't match** … Make the route's `:id` and the name in `const { id }` match. For `:productId`, use `const { productId }`.
- **`'product' is possibly 'undefined'`** … Check the result of `find` with `if (!product)` before using it.
