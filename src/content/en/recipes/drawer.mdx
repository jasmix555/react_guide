## Don't build it yourself — hand it to `<dialog>` {#native-first}

Build a drawer or modal from scratch and you end up writing all of **focus trapping** (Tab keys can't escape to the page behind), **close on Esc**, and the **dimmed backdrop** yourself. It's quietly a lot of work, and easy to get wrong.

Open a `<dialog>` element with `showModal()` and these come **built in from the start**. Opening and closing is just two methods.

```ts title="Open and close"
ref.current?.showModal() // open (with backdrop, focus trapping, and Esc)
ref.current?.close() // close
```

<Callout type="warn">

Be precise about what "built in" covers, because one item is missing and almost everyone assumes it isn't:

| Behaviour | Free with `showModal()`? |
| --- | --- |
| Dimmed backdrop (`::backdrop`) | Yes |
| Focus trapped inside | Yes |
| Esc closes it | Yes |
| Everything behind made inert | Yes |
| **Clicking the backdrop closes it** | **No — you add this** |

The backdrop is drawn for you, but it does nothing when clicked. That's the next section.

</Callout>

## Close it when the outside is clicked {#backdrop}

Since `::backdrop` is a pseudo-element, there's nothing to attach a handler to. The trick is what a backdrop click reports as its target:

**A click on the backdrop lands on the `<dialog>` element itself.** A click on the menu inside lands on the inner element you clicked. So comparing the target is the whole test:

```tsx
<dialog
  ref={ref}
  onClick={(e) => {
    if (e.target === ref.current) ref.current.close()
  }}
>
  <div className={styles.panel}>{/* menu contents */}</div>
</dialog>
```

The inner `<div>` matters as much as the handler. Without it, the empty strip below the last link is still the `<dialog>` element — so clicking inside your own menu would close it. Give the panel `height: 100%` so it covers the dialog completely, and "target is the dialog" can only mean the backdrop:

```scss title="Drawer.module.scss (addition)"
.panel {
  display: flex;
  flex-direction: column;
  height: 100%;
}
```

<Callout type="note">

This is the same idea as the [Modal recipe](/recipes/modal), where the overlay is a real `<div>` and the panel calls `stopPropagation()`. Two ways to answer the same question — "did the click land outside?" — and `<dialog>` needs the target comparison because its backdrop isn't an element you can put a handler on.

</Callout>

## The Drawer component {#drawer-body}

Create a new file at `src/components/Drawer/Drawer.tsx` and paste in the whole thing.

```tsx title="src/components/Drawer/Drawer.tsx (new file, full source)"
import { useRef } from 'react'

import styles from './Drawer.module.scss'

interface DrawerLink {
  label: string
  href: string
}

export function Drawer({ items }: { items: DrawerLink[] }) {
  const ref = useRef<HTMLDialogElement>(null)

  return (
    <>
      <button
        type="button"
        aria-label="Open menu"
        onClick={() => ref.current?.showModal()}
      >
        Menu
      </button>

      <dialog
        ref={ref}
        className={styles.drawer}
        aria-label="Menu"
        onClick={(e) => {
          if (e.target === ref.current) ref.current.close()
        }}
      >
        <div className={styles.panel}>
          <button type="button" aria-label="Close" onClick={() => ref.current?.close()}>
            ✕
          </button>
          <nav>
            {items.map((item) => (
              <a key={item.href} href={item.href} onClick={() => ref.current?.close()}>
                {item.label}
              </a>
            ))}
          </nav>
        </div>
      </dialog>
    </>
  )
}
```

Three things to note. Grab the real `<dialog>` with `ref` and call `showModal()` from the hamburger's `onClick`. **Close it with `close()` when a link is pressed** (it's natural for a menu to close once you pick something). And the `onClick` on the dialog is what adds backdrop-close.

<JsNote feature="Why e.target and not e.currentTarget" to="/guide/components/events">

`e.currentTarget` is always the element the handler is attached to — here, the dialog, every single time. It would make the condition permanently true.

`e.target` is where the click **actually landed**, before it bubbled up. That's the one carrying the information you want: the backdrop reports the dialog, a link reports the link.

</JsNote>

## Slide it in from the side {#animate}

By default a `<dialog>` appears in the center of the screen. Turn it into a tall sheet at the right edge and make it slide. Take the closed state (off to the right = `translateX(100%)`) as the base, and move it to `translateX(0)` once `[open]` is applied.

```scss title="Drawer.module.scss (key parts)"
.drawer {
  position: fixed;
  inset: 0 0 0 auto; // pinned to the right edge, full height
  width: min(320px, 85vw);
  margin: 0;
  padding: 0; // so .panel can fill it edge to edge
  transform: translateX(100%);
  transition:
    transform 0.25s ease,
    display 0.25s ease allow-discrete,
    overlay 0.25s ease allow-discrete;
}

.drawer[open] {
  transform: translateX(0);
}

// The "starting position" for opening. Without this it just pops in.
@starting-style {
  .drawer[open] {
    transform: translateX(100%);
  }
}
```

`padding: 0` is doing quiet work here too: with padding, the strip between the dialog's edge and the panel is still the dialog, so clicking just inside the drawer would close it.

<JsNote feature="@starting-style and allow-discrete">

Because opening a `<dialog>` switches its `display`, an ordinary `transition` alone won't animate it. `@starting-style` sets the "starting position at the moment it opens," and `allow-discrete` says "keep showing it all the way through while closing." On older browsers that don't support these, it just pops open and closed with no animation (i.e. nothing breaks).

</JsNote>

## Lock background scroll {#scroll-lock}

While it's open, being able to scroll the page behind it is distracting. Without adding any JavaScript, you can target "a page with an open `<dialog>`" using CSS `:has` and stop it.

```scss title="Drawer.module.scss (addition)"
:global(html:has(dialog[open])) {
  overflow: hidden;
}
```

## When it doesn't work {#trouble}

- **Clicking the background doesn't close it** … The `onClick` target comparison is missing. `showModal()` alone never closes on a backdrop click — check you didn't only add the CSS.
- **It closes when you click inside the menu** … The panel isn't covering the dialog. Add `height: 100%` to `.panel` and `padding: 0` to the dialog.
- **It closes on every click, even a link** … You compared `e.currentTarget` instead of `e.target`, so the condition is always true.
- **There's no backdrop at all** … You opened it with `show()` instead of `showModal()`. `show()` gives you neither the backdrop nor focus trapping.
- **It doesn't animate** … Check that `@starting-style` and `allow-discrete` are present. Opening and closing still work without them.

## Summary {#summary}

<SummaryBox>

- Don't build a drawer yourself — `<dialog>` + `showModal()` / `close()` gives you Esc, focus trapping, inert background, and the dimmed backdrop
- **Closing on a backdrop click is not included.** Add `onClick` on the dialog and close when `e.target === ref.current`
- That test only holds if an inner panel with `height: 100%` fills the dialog and the dialog has `padding: 0`
- Position it with `inset: 0 0 0 auto` at the right edge. Slide it with `transform` + `@starting-style`
- Lock background scroll with `overflow: hidden` on `html:has(dialog[open])`

</SummaryBox>
