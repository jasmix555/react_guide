## Responding to clicks {#what}

Do something when a button is pressed — you write this with an **event**. The one you'll use most is `onClick` for clicks. Add `onClick` to a `<button>` and **pass it the function you want to run**.

```tsx
function BuyButton() {
  function handleClick() {
    console.log('The buy button was clicked')
  }

  return <button onClick={handleClick}>Buy</button>
}
```

Every time the button is pressed, `handleClick` runs and a message appears in the console (`F12`). It's similar to HTML's `onclick`, but in JSX it's camelCase `onClick`, and **what you pass is the function itself, not a string**.

Let's break down `onClick={handleClick}`.

```tsx
<button onClick={handleClick}>Buy</button>
//      ↑        ↑
//      │        └─ pass only the function's name (handleClick, without ())
//      └─ the event name (runs on click)
```

- **Event name** … `onClick` fires when the button is clicked
- **Pass only the function's name** … write `handleClick`. Don't add `()` to make it `handleClick()`

Here's `BuyButton` as a full file.

```tsx title="src/components/BuyButton/BuyButton.tsx (full file)"
export function BuyButton() {
  function handleClick() {
    console.log('The buy button was clicked')
  }

  return (
    <button type="button" onClick={handleClick}>
      Buy
    </button>
  )
}
```

<JsNote feature="What you pass to onClick is only the function's name">

`onClick={handleClick}` is exactly Part 2's [Passing functions as values](/guide/javascript/functions-as-values). You're passing the **function `handleClick` by name only**. React receives it as "when clicked, please run this function" and calls it at the moment the button is actually pressed.

</JsNote>

## Break it on purpose: `onClick={fn()}` runs before the click {#break-call}

The most common mistake is adding `()` when you pass it. The trap we covered in Part 2 shows up here as a real-world symptom.

```tsx
return <button onClick={handleClick()}>Buy</button>
```

Written this way, **`handleClick` runs the moment the screen appears, even though you haven't pressed the button**. And when you do click, nothing happens anymore.

The reason is just as in Part 2. `handleClick()` is "the **result of calling the function right now**". So what gets passed to `onClick` isn't a function — it's "the value left over after it already ran". What you pass to `onClick` is always **`handleClick` (name only, no `()`)**. When something "runs even though you didn't click" or "doesn't run when you click", first suspect that you added `()`.

## When you want to pass an argument, wrap it in an arrow function {#arrow}

Sometimes you want to "call a function with an argument on click". But writing `onClick={buy(product)}` gives you the trap from before — it runs immediately. So you **wrap it in an arrow function** to pass it.

```tsx
<button onClick={() => buy(product)}>Buy this</button>
```

`() => buy(product)` is "a function that runs `buy(product)` when called". Since what you pass is **the function itself**, it doesn't run immediately; `buy(product)` runs only when the button is clicked. "When you want to pass an argument, wrap it in an arrow function" — memorize this as a standard pattern.

Let's break down `onClick={() => buy(product)}`.

```tsx
<button onClick={() => buy(product)}>Buy this</button>
//               ↑     ↑
//               │     └─ call it with an argument (pass product to buy)
//               └─ wrap it in an arrow function (runs on click)
```

- **Wrap it in an arrow function** … `() => …` makes "a function that runs when called"
- **Call it with an argument** … inside the wrapper you can call `buy(product)` and pass an argument

`onClick={() => alert('Added to cart')}` passes a function that runs `alert(...)` when clicked. If you wrote `onClick={alert('Added to cart')}`, the alert would fire the moment it renders. This is "when you want to call with an argument, wrap it in an arrow function" at work.

## Changing the screen comes from "state" {#next}

The events so far only did a `console.log` or an `alert`. To "change the actual display on the screen when pressed" — like increasing the cart count, or opening a modal — you need a mechanism called **state**.

That's because in React, **rewriting an ordinary variable doesn't update the screen**. Values tied to the screen are held in state. We'll cover this in detail in the next part (more on it later). For now, it's enough to have the shape of "responding to clicks" (`onClick={function}`) down.

## Pattern catalog: event handlers {#catalog}

```tsx
<button onClick={handleClick}>Submit</button>          // pass a function (no () added)
<button onClick={() => buy(product)}>Buy</button>       // wrap in an arrow function to pass an argument
<input onChange={(e) => setName(e.target.value)} />    // pull the value out of the event

// named handler … pull a multi-line body out into a function and pass the name only
// inline arrow   … for one line, write onClick={() => setOpen(true)} directly
```

The basic form is `onClick={fn}`. Only wrap it as `onClick={() => fn(x)}` when you need an argument.

## When it doesn't work {#trouble}

- **Runs even though you didn't click / runs only once** … you added `()` as in `onClick={fn()}`. Change it to `onClick={fn}`.
- **Nothing happens when you click** … same thing — check for a missing or extra `()`, or a misspelled function name.
- **The screen doesn't change when pressed** … rewriting an ordinary variable doesn't update the screen. Use state from the next part.
