## Turning the data shape into a type {#product}

Each item in `products.json` has a fixed shape. Let's capture that shape as a `Product` type. Since `category` is always one of three fixed values, we make it a [literal union](/guide/typescript/union-literal).

```ts title="src/types/product.ts"
export interface Product {
  id: string
  name: string
  price: number
  category: 'kitchen' | 'living' | 'outdoor'
  imageUrl: string
  tags: string[]
  inStock: boolean
}
```

With `category: 'kitchen' | 'living' | 'outdoor'`, the type catches typos like `'kitchin'` for you. `tags: string[]` means "an array of strings".

## Reading products.json with types {#typed-json}

We import `products.json` and add a type to say "this is an array of `Product`". We use `as Product[]`.

```ts title="src/data/products.ts"
import productsData from './products.json'

import type { Product } from '@/types/product'

export const products = productsData as Product[]
```

Now `products` is treated as `Product[]` (an array of Product). `products[0].name` gets autocomplete, and `products[0].prise` (a typo) is stopped with a red underline.

<Callout type="warn" title="as is a promise that you guarantee the shape">

`as Product[]` is a way (a type assertion) of telling TypeScript "I guarantee this JSON has the `Product` shape". TypeScript **does not verify the actual contents of the JSON**. So you have to keep the `Product` type and the real contents of `products.json` in sync yourself (change only one and they drift apart).

</Callout>

## Break it on purpose: a category not in the union {#break}

Let's see how the `category` union stops mistakes in your data. We'll write a `Product` object with a category that doesn't exist.

```ts title="A category that doesn't exist"
const p: Product = {
  id: 'x',
  name: 'Test',
  price: 100,
  category: 'kitchin', // ← typo (should be kitchen)
  imageUrl: '',
  tags: [],
  inStock: true,
}
```

`'kitchin'` gets a red underline, and you see this.

```
Type '"kitchin"' is not assignable to type
'"kitchen" | "living" | "outdoor"'.
```

"`'kitchin'` is not any of the three allowed categories." If you had used `category: string`, this typo would slip through, and later you'd be puzzling over "why doesn't this one product show up in the filter?"

## When things go wrong {#trouble}

- **`products[0].name` becomes `any` / autocomplete doesn't work** … Check that you added the type with `as Product[]`.
- **`Type 'X' is not assignable` (category)** … The value in `products.json` and the `Product` type's union have drifted apart. Line one up with the other.
