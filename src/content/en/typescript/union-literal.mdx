## Literal types: allow only specific values {#literal}

`string` is "any string at all," but sometimes you want to limit it to **only specific strings** — like `variant` only being allowed to hold `'primary'` or `'secondary'`. For that, you make the value itself into a type (a literal type).

```ts
type Variant = 'primary' | 'secondary' | 'ghost'
```

```ts
type Variant = 'primary' | 'secondary' | 'ghost'
//             ↑           ↑
//             │           └─ | means "or"
//             └─ exactly one of these three strings
```

`|` means "or." A variable of type `Variant` can't hold anything outside these three. This is what you used on the [button-variants page](/guide/components/button-variants).

## union types: one of several {#union}

You can join more than just strings with `|` — you can join types together too. You can express **one of several types**, like "`string` or `number`" or "`Product` or `null`." This is called a union type.

```ts
type Id = string | number // string or number
```

A common one in React is **`X | null`**. It expresses state like "`null` if nothing is chosen yet, `Product` once chosen."

```tsx
// the currently selected product; null if none yet
const [selected, setSelected] = useState<Product | null>(null)
```

## narrowing: narrow the type with if {#narrowing}

A union like `Product | null` can't have its contents used as-is (it might be `null`). When you check it with `if`, TypeScript **narrows the type beyond that point** for you. This is called narrowing.

```tsx
function label(selected: Product | null): string {
  if (selected === null) {
    return 'Not selected'
  }
  // from here on, selected is narrowed to Product (not null)
  return selected.name
}
```

After passing through `if (selected === null) return ...`, TypeScript knows "`selected` is no longer `null` — it's a `Product`," so you can safely write `selected.name`.

## Break it on purpose: pass a value that isn't in the union {#break}

Let's watch a literal union do its job. We'll assign a value that isn't in the `'primary' | 'secondary'` type.

```ts title="A value not in the union"
type Variant = 'primary' | 'secondary'

const v: Variant = 'primani' // ← typo
```

A red squiggle appears on `'primani'`, saying:

```
Type '"primani"' is not assignable to type 'Variant'.
```

"`'primani'` can't go into `Variant` (either primary or secondary)." Fix the spelling and it disappears. If the type had been `string`, this typo would have slipped right through.

## Syntax catalog: union and literals {#catalog}

```ts
type Variant = 'primary' | 'secondary' // literal union
type Id = string | number // union of types
type Nullable = Product | null // value or nothing

// narrowing
function f(x: string | null) {
  if (x === null) return 0
  return x.length // here x is string
}
```

## When things go wrong {#trouble}

- **`'X' is possibly 'null'`** … You're using the contents of `X | null` without a `null` check. Narrow it with `if (x === null)` first.
- **The literal isn't working** … Check that the type hasn't become `string`. To fix the choices, write `'a' | 'b'`.
