## This mixin is "our standard" {#why}

The shared `_mixin.scss` (`getVw`, `mq`) we've used all along for LP work can be used as-is in React too. Instead of relearning a whole new way to think about styling, the goal of this page is to **bring familiar tools into SCSS Modules**. First, let's grab the file.

<Download href="/downloads/_mixin.scss" filename="_mixin.scss">Download _mixin.scss</Download>

Inside are the usual functions and mixins.

- **`getVw($px, $viewport)`** … Converts px to vw (scales with the screen width).
- **`mq($breakpoint)`** … A media query. The default is `medium` (**767px and under = SP**).
- `fontSizeVw` / `fontSizeRem` / `lineHeight` / `getRatio` … Helpers for fonts and ratios.

The behavior is the same, but it runs without warnings on newer Dart Sass. It's a good idea to fix your own master copy the same way.

</Callout>

## Put it in the styles folder {#place}

Put the downloaded `_mixin.scss` in your project's `src/styles/`.

```
my-shop/src/
├─ styles/
│  ├─ _mixin.scss     ← put it here
│  └─ tokens.scss     ← color tokens (previous page)
├─ components/
└─ ...
```

The leading `_` (underscore) in the file name is Sass's marker for "this is a partial and isn't output on its own." Keep `_mixin.scss` as-is.

## Load it from .module.scss with @use {#use}

At the **top** of each component's `.module.scss`, load it with `@use`. Modern Sass uses **`@use`**, not the `@import` from the LP days.

```scss title="ProductCard.module.scss (top)"
@use '../../styles/mixin' as *;
```

```scss
@use '../../styles/mixin' as *;
//   ↑                      ↑
//   │                      └─ as * = call getVw / mq directly, with no namespace
//   └─ relative path to styles/_mixin.scss (drop the leading _ and .scss)
```

Adding `as *` lets you use `getVw(...)` and `@include mq` exactly the way you always have (if you want a namespace, you can write `as m` and use `m.getVw(...)` instead). The relative path is the route from that file to `styles/mixin` (from `components/ProductCard/`, that's `../../styles/mixin`).

## getVw: turn px into vw {#getvw}

`getVw` converts **a design's px into vw that scales with the screen width**. The default reference width is **750** (= the width of an SP design).

```scss
.title {
  padding-left: getVw(30); // equivalent to 30px in a 750px design; shrinks on narrower screens
}
```

```scss
padding-left: getVw(30);
//            ↑      ↑
//            │      └─ the px you want to convert (the size in the design)
//            └─ px → vw. Default reference width is 750 (SP design)
```

When you want to base it on a PC design (a different width), pass the reference width as the second argument. And **capping the maximum with `min()`** is our go-to.

```scss
// On PC, scale with vw but never exceed 148px
padding-left: min(getVw(148, 1200), 148px);
```

`getVw(148, 1200)` is "148px in a 1200px-wide design" turned into vw. `min(that, 148px)` stops it at 148px even when the screen is wider than the design. As it gets narrower, it shrinks by the vw amount.

## mq: switch to SP at 767px {#mq}

`mq` is a mixin that groups styles for "that width **and under**." The default is **`medium` = 767px**. Our "PC → SP" switch is usually right here.

```scss
.box {
  // PC styles (this is the base)
  display: flex;
  gap: 40px;

  @include mq {
    // only at 767px and under (SP) does this override
    display: block;
    gap: 0;
  }
}
```

Inside `@include mq { ... }` is for SP. For a different width, pass a key from `$mq-breakpoints` (`small` / `medium` / `large` / `xlarge`), like `@include mq(large)`.

## Real example: the usual `&__inner` {#example}

This shape we often write on the job works as-is too.

```scss title="Section.module.scss"
@use '../../styles/mixin' as *;

.section {
  &__inner {
    width: min(100%, 1200px);
    margin: 0 auto;
    padding-left: min(getVw(148, 1200), 148px); // PC: scales with vw, max 148px

    @include mq {
      // 767px and under (SP)
      width: auto;
      padding-left: 0;
    }
  }
}
```

There are three things to read here. On **PC**, `min(getVw(...), 148px)` means "shrinks with vw but never exceeds 148px." At **767px and under**, the `@include mq` block switches to the SP layout (`padding-left: 0`). Where you want vw to take effect on the SP side, use a 750-based `getVw` like `getVw(30)`.

## When things go wrong {#trouble}

- **`Undefined function getVw` / `no mixin named mq`** … Check that you wrote `@use '.../mixin' as *;` at the top of that `.module.scss` (it's needed in every file).
- **`@use` rules must be written before any other rules** … `@use` must always go at the **top** of the file.
- **The path isn't found** … Check the relative path (from `components/ProductCard/`, that's `../../styles/mixin`). Drop the `_` and `.scss`.
