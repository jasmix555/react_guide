## Nesting {#nesting}

In CSS, you write out the parent/child relationship in full every time. SCSS lets you **nest**. Writing `.body` inside `.card` means "the `.body` inside `.card`."

```scss title="SCSS (written with nesting)"
.card {
  border: 1px solid #e5e7eb;

  .body {
    padding: 12px;
  }

  .name {
    font-weight: 600;
  }
}
```

At build time, this expands into ordinary CSS.

```css title="CSS after conversion"
.card { border: 1px solid #e5e7eb; }
.card .body { padding: 12px; }
.card .name { font-weight: 600; }
```

Because you can group related things in one place, it's easier to follow.

<Callout type="warn" title="Don't nest too deep">

Nesting 3 or 4 levels deep actually gets harder to read, and it also raises specificity, making it harder to override. Aim for **2 levels at most**.

</Callout>

## `&` means "yourself" {#ampersand}

`&` refers to "the selector you're currently writing." Use it to group `:hover` and state classes.

```scss
.card {
  transition: transform 0.15s ease;

  &:hover {
    transform: translateY(-2px); // means .card:hover
  }
}
```

`&:hover` expands to `.card:hover`. Using `&` lets you keep everything about `.card` self-contained inside `.card`.

## `$` variables: the same value in one place {#variables}

If you write the same color or spacing over and over, you'll have to fix every occurrence when it changes. Group them into an SCSS **`$` variable** and you only fix one place.

```scss
$radius: 12px;
$line: #e5e7eb;

.card {
  border: 1px solid $line;
  border-radius: $radius;
}
```

<JsNote feature="$ variables get their values 'baked in' at build time">

An SCSS `$` variable is **replaced with its actual value at the moment of the build**. In the example above, the output CSS has `12px` and `#e5e7eb` written directly. You can't switch it at runtime (for theming, etc.). The CSS `--variable`, which can do that, is covered on the next page.

</JsNote>

## `@mixin`: reuse a group of styles {#mixin}

When you want to reuse "a group of multiple properties," define it with `@mixin` and call it with `@include`. It's a good fit for chunks used all over, like resetting a button's look.

```scss
@mixin button-reset {
  border: none;
  background: transparent;
  padding: 0;
  cursor: pointer;
}

.fav {
  @include button-reset; // the 4 lines above get expanded here
  color: crimson;
}
```

## Syntax catalog: SCSS features {#catalog}

```scss
// nesting
.card {
  .body { padding: 12px; }   // → .card .body
  &:hover { ... }            // → .card:hover
  &.active { ... }           // → .card.active (when active is added to itself)
}

// variables
$accent: #4f46e5;
.btn { background: $accent; }

// mixin
@mixin center { display: grid; place-items: center; }
.badge { @include center; }
```

## When things don't work {#trouble}

- **Nesting doesn't work** … Check that you're writing in `.module.scss` (SCSS). Plain `.css` can't use nesting (note: newer CSS allows some of it, but here we assume SCSS).
- **`&:hover` affects a different element** … `&` is "that selector itself." If you want it on a child, nest it (`.card { .body:hover { ... } }`).
