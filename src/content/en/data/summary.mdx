## Full review of this part {#recap}

We took a list that used to be a direct import and made it run on a real request. Here are the key points.

- **import vs fetch** … `import` bakes the data in (instant, fixed); `fetch` is a request (takes time, can fail, always current).
- **The skeleton of a fetch** … `await fetch(url)` → **`if (!res.ok) throw`** → `await res.json()`. A 404 doesn't make fetch fail, so you check `res.ok` yourself.
- **Where to call it** … in the render body it's an infinite loop. Use `useEffect(() => {...}, [])` to run it just once. Clean up with `ignore = true`.
- **Three states** … hold `status` as the union `'loading' | 'error' | 'success'`, route it with `try` / `catch`, and switch what you show on screen.
- **Custom hook** … bundle the fetch into `useProducts()` (a function that starts with `use`), return `{ products, status }`, and reuse it.

Handling "waits and can fail" with three states — this shape is the same for any request.

Why do you write `if (!res.ok) throw ...` after `fetch`?

</Exercise>

<Exercise answer="You get an infinite loop. fetch → setState → re-render → fetch again in the body → … it never stops. Put it inside useEffect(() => { ... }, []) and it runs only once at the start.">

What happens if you `fetch` and `setState` directly in the component body (before the return)? How do you fix it?

</Exercise>

How do you hold a request's three states in `status`, and how do you switch what shows on screen?
