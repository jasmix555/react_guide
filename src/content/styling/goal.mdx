## なぜ「スタイリング」を 1 つのパートにするのか {#why}

LP 制作では、CSS を直接書いていました。React でも CSS は書きますが、**書き方と管理の仕方**が変わります。とくに困るのが、プロジェクトが大きくなると起きる **クラス名の衝突** です。

- `A.css` に `.card`、`B.css` にも `.card`。どちらかが、もう片方を上書きしてしまう。
- 「この `.title` のスタイル、どのファイルで効いてるんだっけ？」が分からなくなる。

SCSS Modules は、この問題を**部品ごとにスタイルを閉じ込める**ことで解決します。`ProductCard.module.scss` に書いた `.card` は、`ProductCard` の中だけで効き、他のファイルの `.card` とは絶対にぶつかりません。この「衝突しない安心感」が、React でスタイルを書く土台になります。

## このパートの進み方 {#roadmap}

上から順に、SCSS Modules を積み上げていきます。

1. **なぜ SCSS Modules か** — グローバル CSS の衝突を、実際に起こして確かめる。
2. **最初の .module.scss** — `import styles` して `className={styles.card}` で当てる。
3. **SCSS の機能** — 入れ子・`&`・変数 `$`・`@mixin` で書きやすくする。
4. **デザイントークンとテーマ** — CSS 変数 `--x` で色をまとめ、ライト／ダークに対応する。
5. **レスポンシブ** — メディアクエリと grid で、スマホでもきれいに並べる。
6. **条件付きクラス** — 在庫やお気に入りの状態で、クラスを出し分ける（clsx）。
7. **通し課題** — 一覧とカードを、実際に仕上げる。

各ページに**コード全文**と**練習**を用意しています。読むだけでなく、`my-shop` で実際に書いて、画面が変わるのを見てください。
