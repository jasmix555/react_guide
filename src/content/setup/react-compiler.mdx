前のページで「React Compiler は付けない」と決めました。ただ、名前も知らないまま素通りするとモヤモヤするので、ここで正体だけ押さえます。**今すぐ使う話ではありません。**

## そもそもコンパイラとは {#compiler}

**コンパイラ（compiler）とは、ある形式のコードを別の形式に変換する道具**です。あなたが書く TypeScript は、ブラウザがそのままでは読めません。それをブラウザの読める JavaScript に変換する——この変換も一種のコンパイルで、Vite が裏でやっています。

<Callout type="analogy">

日本語の原稿を英語に翻訳する翻訳者のようなものです。書いた人（あなた）と読む人（ブラウザ）の間に立って、言葉を変換します。

</Callout>

## React Compiler は何をするコンパイラか {#react-compiler}

React には「同じ結果になる計算を、毎回やり直して無駄になる」という場面があります。従来はそれを防ぐために、`useMemo` や `useCallback` という道具を**人間が手で書いて**最適化していました（後のパートで学びます）。

**React Compiler は、その最適化を自動でやってくれるコンパイラ**です。人間が `useMemo` を書かなくても、必要な場所に相当する処理を自動で入れてくれます。うまくいけば、最適化を意識せずに速いアプリが書けます。

## なぜ今は付けないのか {#why-not}

便利なのに付けないのには、はっきりした理由があります。

学習の目的は「**なぜ React が再描画するのか**」「**どこが無駄になるのか**」を自分の頭で理解することです。React Compiler を最初から効かせると、その最適化が裏で自動的に起きてしまい、**「自分で書いたらどうなるか」が見えなくなります**。

具体的には、後半の Part 9「state と hooks」で `useMemo` / `useCallback` / `React.memo` を**手で書いて**「どこが無駄で、どう防ぐか」を確かめます。React Compiler を先に効かせると、その最適化が読者の手元で自動的に起きてしまい、**練習が「自分の画面では成り立たない」ことになります**（あとで詳しくやります）。

だから、まずは自動化なしで仕組みを理解し、**必要になったら後から足す**。React Compiler は、素のプロジェクトにいつでも追加できます。

<Deeper title="後から React Compiler を足す方法（今はやらない）">

`@vitejs/plugin-react` に React Compiler の設定を渡すことで有効化できます。手順は [公式ドキュメント](https://react.dev/learn/react-compiler)にまとまっています。チーム全員が再描画と最適化を理解したうえで、「手書きの最適化をやめて自動に任せる」と決めたタイミングで導入するのが健全です。

</Deeper>

<Deeper title="Babel・SWC・Oxc — 変換の道具たち（今は何もしなくていい）">

コードを「ブラウザが読める形」に変換する道具は、実は何種類かあります。**Babel・SWC・Oxc は、どれも同じ仕事（JSX と新しい構文を、ブラウザが読める JavaScript に変換する）をする道具**で、速さと新しさが違うだけです。

- **Babel** … 長年の定番。
- **SWC** … Babel を速くした後発。少し前の create-vite には「TypeScript + SWC」という選択肢があり、多くの記事が勧めています。
- **Oxc** … さらに新しく、create-vite 9 が**既定で使う**ようになった変換エンジン。

つまり、古い記事が「SWC を選べ」と書いていても、今の作成画面には出てきません。**あなたは何も選ぶ必要がなく、既定の Oxc がそのまま使われます。** 名前を見かけたら「変換の道具の話だな」と分かれば十分です。

</Deeper>

<SummaryBox>

- コンパイラは「コードをある形式から別の形式へ変換する道具」。TS→JS の変換もその一種
- React Compiler は `useMemo` などの最適化を自動でやってくれるコンパイラ
- 学習中は仕組みを自分で理解したいので付けない。必要になったら後から足せる

</SummaryBox>
