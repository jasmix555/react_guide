React のプロジェクトを作る方法はいくつかあります。ここで「どれで作るか」を決めます。結論から言うと **Vite** で作りますが、なぜかを知っておくと、ネットの古い記事に惑わされなくなります。

## Vite とは {#what}

**Vite（ヴィート）は、React の開発サーバとビルドをまとめて面倒みてくれる道具**です。あなたが書いた `.tsx` を、ブラウザが読める形に変換し、保存した瞬間に画面へ反映し、最後に本番用のファイルへまとめる——この一連を全部やります。特徴は**起動と反映がとにかく速い**ことです。

## 昔の定番 create-react-app は使わない {#cra}

少し前まで、React の入門記事はどれも **create-react-app（CRA）** で始まっていました。今これを使ってはいけません。

CRA は動作が遅く、メンテナンスも止まり、**React 公式サイトはすでに CRA を推奨から外しました**。今から CRA で始めると、遅いうえに、詰まったときの情報も古いものばかりで、いいことがありません。ネットで `create-react-app` と書いた記事を見たら、**それは古い記事だと判断して読み飛ばして大丈夫**です。

## Next.js との違い {#next}

もう一つよく名前を聞くのが **Next.js** です。これは Vite と同じレイヤーの道具ではありません。**Next.js は「フレームワーク」**で、ルーティングやサーバー側の処理まで最初から組み込まれた、大きな枠組みです。

強力ですが、React そのものを学ぶ段階では**覚えることが多すぎて、React の学習とフレームワークの学習が混ざってしまいます**。SEO やサーバーサイドが本当に必要になったら Next.js へ進む道はちゃんと用意されています（このガイドの後半で扱います）。まずは余計なものが乗っていない Vite で、React の芯を学びます。

<Std
  decision="学習と、フロントだけで完結する多くの案件は Vite で作る"

Vite は起動が速く、構成がシンプルで、React の考え方をそのまま学べます。LP 制作の延長で「動きのあるフロント」を作る、という私たちの案件像とも相性がいい選択です。

</Std>

<Deeper title="SWC・Babel・Rolldown といった言葉について">

Vite の内部では、コードを変換する小さな道具（Babel や SWC、Oxc など）が動いています。名前を覚える必要は今はありません。「Vite が中で速い変換道具を使っている」くらいの理解で十分で、どれを使うかの選択肢はこのあとのページで出てきたときに説明します。

</Deeper>

<SummaryBox>

- Vite は React の開発サーバ＋ビルドをまとめて速くやってくれる道具
- create-react-app は公式が推奨をやめた古い方法。記事で見たら読み飛ばしてよい
- Next.js はフレームワークで学習には重い。まずは Vite で React の芯を学ぶ

</SummaryBox>
