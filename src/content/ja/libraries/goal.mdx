## ライブラリは「出来合いの部品」 {#what}

ライブラリとは、**誰かが作って公開してくれた、出来合いの部品**です。日付をきれいに整える、アニメーションを付ける、クラス名を組み立てる——こうした「よくある作業」を、自分でゼロから書かずに借りてこられます。

LP 制作でも、jQuery のプラグインやスライダーを読み込んで使っていました。あれと同じ発想です。ただし React では、`<script>` で読み込むのではなく、**`npm install` で自分のプロジェクトに取り込む**という形になります。

<Callout type="analogy">

料理でいえば、だしを一から取るか、市販のだしパックを使うか、です。市販品（ライブラリ）は速くて確実ですが、棚に増やしすぎると管理が大変になります。「何が入っているか」を把握できる範囲で使うのがコツです。

</Callout>

## 入れる前に「なぜ入れるか」を言えるように {#why}

この章で一番伝えたいのは、テクニックではなく **姿勢** です。**部品を足す前に、いちど「本当に要るか」を考える**——これだけで、後々のトラブルが大きく減ります。

理由は 2 つあります。1 つは、入れた部品は**ずっと面倒を見続けることになる**から（更新、不具合、他の部品との相性）。もう 1 つは、**標準の機能や、すでに入っている部品で足りることが多い**から。「これ、ライブラリ要らなかったな」は本当によく起きます。

だからこの章では、個々のライブラリの前に、まず「**どう選ぶか・入れると何が変わるか**」を先に扱います。

## このタブの歩き方 {#roadmap}

このタブは、大きく 2 段構えです。

1. **ライブラリとの付き合い方（このパート）** — `npm install` が何を書き換えるか、選び方、型定義が別パッケージのとき、環境変数、消す・入れ替える・上げる。あわせて、コアのレッスンから使う `sass` / `clsx` / `react-router` / `motion` の入れ方。**「入れる前の判断」と「入れる手順」**の土台です。
2. **ライブラリごとの実践パート** — **Framer Motion** をはじめ、GSAP・Swiper・Tailwind・React Icons などを、**1 ライブラリ＝1 パート**で、入れ方から実際の使い方まで深掘りします（順次追加）。

必要なところだけ拾い読みして構いません。作りたい UI が先にあるなら、[レシピ](/recipes/modal)からの逆引きも近道です。
