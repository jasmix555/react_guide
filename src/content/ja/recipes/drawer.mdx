## 自作せず `<dialog>` に任せる {#native-first}

ドロワーやモーダルを自作すると、**フォーカスの閉じ込め**（Tab キーが後ろのページに逃げない）、**Esc で閉じる**、**背景の暗幕**を全部自分で書くことになります。これは地味に大変で、抜けやすい部分です。

`<dialog>` 要素を `showModal()` で開くと、これらが**最初から付いてきます**。開閉は 2 つのメソッドだけです。

```ts title="開く・閉じる"
ref.current?.showModal() // 開く（暗幕・フォーカス閉じ込め・Esc 付き）
ref.current?.close() // 閉じる
```

<Callout type="warn">

「標準で付いてくる」の範囲は正確に押さえてください。1 つだけ含まれておらず、しかもほぼ全員が含まれていると思い込む項目があります。

| 挙動 | `showModal()` で無料？ |
| --- | --- |
| 暗幕（`::backdrop`） | 付く |
| フォーカスが中に閉じ込められる | 付く |
| Esc で閉じる | 付く |
| 背後が操作不能になる | 付く |
| **背景クリックで閉じる** | **付かない（自分で足す）** |

暗幕は描かれますが、押しても何も起きません。それが次の節です。

</Callout>

## 外側を押したら閉じる {#backdrop}

`::backdrop` は擬似要素なので、ハンドラを付ける相手がいません。鍵になるのは、背景クリックがどこを target として報告するかです。

**背景のクリックは `<dialog>` 要素そのものに当たります。** 中のメニューを押したときは、押した中の要素に当たります。つまり target を比べるだけで判定できます。

```tsx
<dialog
  ref={ref}
  onClick={(e) => {
    if (e.target === ref.current) ref.current.close()
  }}
>
  <div className={styles.panel}>{/* メニューの中身 */}</div>
</dialog>
```

内側の `<div>` はハンドラと同じくらい重要です。これが無いと、最後のリンクより下の空いている部分はまだ `<dialog>` なので、自分のメニューの中を押したのに閉じてしまいます。パネルに `height: 100%` を与えて dialog を覆い切れば、「target が dialog」＝背景、と言い切れます。

```scss title="Drawer.module.scss（追記）"
.panel {
  display: flex;
  flex-direction: column;
  height: 100%;
}
```

<Callout type="note">

考え方は[モーダルのレシピ](/recipes/modal)と同じです。あちらはオーバーレイが本物の `<div>` で、パネル側が `stopPropagation()` を呼びます。「クリックは外側だったか？」という同じ問いへの答え方が 2 通りあるだけで、`<dialog>` は暗幕がハンドラを付けられる要素ではないので target の比較になります。

</Callout>

## Drawer 本体 {#drawer-body}

`src/components/Drawer/Drawer.tsx` を新規作成して、この全文を貼り付けてください。

```tsx title="src/components/Drawer/Drawer.tsx（新規作成・全文）"
import { useRef } from 'react'

import styles from './Drawer.module.scss'

interface DrawerLink {
  label: string
  href: string
}

export function Drawer({ items }: { items: DrawerLink[] }) {
  const ref = useRef<HTMLDialogElement>(null)

  return (
    <>
      <button
        type="button"
        aria-label="メニューを開く"
        onClick={() => ref.current?.showModal()}
      >
        メニュー
      </button>

      <dialog
        ref={ref}
        className={styles.drawer}
        aria-label="メニュー"
        onClick={(e) => {
          if (e.target === ref.current) ref.current.close()
        }}
      >
        <div className={styles.panel}>
          <button type="button" aria-label="閉じる" onClick={() => ref.current?.close()}>
            ✕
          </button>
          <nav>
            {items.map((item) => (
              <a key={item.href} href={item.href} onClick={() => ref.current?.close()}>
                {item.label}
              </a>
            ))}
          </nav>
        </div>
      </dialog>
    </>
  )
}
```

ポイントは 3 つです。`ref` で本物の `<dialog>` を掴み、ハンバーガーの `onClick` で `showModal()`。**リンクを押したら `close()`** で閉じる（メニューは選んだら閉じるのが自然です）。そして dialog の `onClick` が、背景クリックで閉じる機能を足している部分です。

<JsNote feature="なぜ e.currentTarget ではなく e.target なのか" to="/guide/components/events">

`e.currentTarget` は常に「ハンドラを付けた要素」——ここでは毎回 dialog です。条件が永久に真になってしまいます。

`e.target` は、バブリングして上がってくる前に**実際にクリックが当たった場所**。欲しい情報を持っているのはこちらです。背景なら dialog を、リンクならリンクを報告します。

</JsNote>

## 横からスライドさせる {#animate}

`<dialog>` は初期状態では画面中央に出ます。これを右端の縦長シートにして、スライドさせます。閉じている状態（右外＝`translateX(100%)`）を基本にし、`[open]` が付いたら `translateX(0)` に動かします。

```scss title="Drawer.module.scss（要点）"
.drawer {
  position: fixed;
  inset: 0 0 0 auto; // 右端いっぱい・上下フル
  width: min(320px, 85vw);
  margin: 0;
  padding: 0; // .panel が端まで埋められるように
  transform: translateX(100%);
  transition:
    transform 0.25s ease,
    display 0.25s ease allow-discrete,
    overlay 0.25s ease allow-discrete;
}

.drawer[open] {
  transform: translateX(0);
}

// 開くときの「開始位置」。これが無いと開いた瞬間にパッと出る。
@starting-style {
  .drawer[open] {
    transform: translateX(100%);
  }
}
```

`padding: 0` もここで地味に効いています。padding があると、dialog の端とパネルの間の帯はまだ dialog なので、ドロワーのすぐ内側を押したときに閉じてしまいます。

<JsNote feature="@starting-style と allow-discrete">

`<dialog>` は開くと `display` が切り替わるため、ふつうの `transition` だけでは動きません。`@starting-style` で「開いた瞬間の開始位置」を、`allow-discrete` で「閉じるときも最後まで見せる」を指定します。対応していない古いブラウザでは、アニメーション無しでパッと開閉します（＝壊れはしません）。

</JsNote>

## 背景スクロールを止める {#scroll-lock}

開いている間、背後のページがスクロールできると気が散ります。JavaScript を足さなくても、CSS の `:has` で「開いている `<dialog>` があるページ」を狙って止められます。

```scss title="Drawer.module.scss（追記）"
:global(html:has(dialog[open])) {
  overflow: hidden;
}
```

## うまくいかないとき {#trouble}

- **背景を押しても閉じない** … `onClick` の target 比較がありません。`showModal()` だけでは背景クリックで閉じることは決してないので、CSS だけ足していないか確認します。
- **メニューの中を押すと閉じる** … パネルが dialog を覆えていません。`.panel` に `height: 100%`、dialog に `padding: 0` を足します。
- **リンクを含め、どこを押しても閉じる** … `e.target` ではなく `e.currentTarget` を比べていて、条件が常に真になっています。
- **そもそも暗幕が出ない** … `showModal()` ではなく `show()` で開いています。`show()` だと暗幕もフォーカス閉じ込めも付きません。
- **アニメーションしない** … `@starting-style` と `allow-discrete` が入っているか確認します。無くても開閉自体は動きます。

## まとめ {#summary}

<SummaryBox>

- ドロワーは自作せず `<dialog>` + `showModal()` / `close()`。Esc・フォーカス閉じ込め・背後の無効化・暗幕が標準で付く
- **背景クリックで閉じるのは含まれない。** dialog に `onClick` を付け、`e.target === ref.current` のとき閉じる
- その判定が成り立つのは、`height: 100%` の内側パネルが dialog を覆い、dialog に `padding: 0` がある場合だけ
- 位置は `inset: 0 0 0 auto` で右端。スライドは `transform` + `@starting-style`
- 背景スクロールは `html:has(dialog[open])` に `overflow: hidden` で止める

</SummaryBox>
