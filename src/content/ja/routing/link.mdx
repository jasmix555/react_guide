<LearnBox>

- `<a>` ではなく `<Link>` で移動する理由（リロードしない）
- `<Link to="...">` の基本
- `NavLink` で「今いるページ」を目立たせる

</LearnBox>

## `<a>` はページ全体を読み直す {#why-link}

LP では、リンクは `<a href="...">` でした。これはブラウザに「そのページを**まるごと開き直せ**」と命じます。SPA でこれをやると、**アプリ全体がリロード**され、真っ白になってから読み込み直します。持っていた state（お気に入り等）も全部消えます。

react-router では、代わりに **`<Link>`** を使います。`<Link>` は、ページを読み直さず、**必要な中身だけを差し替え**ます。速く、state も保たれます。

```tsx
import { Link } from 'react-router-dom'

<Link to="/product/p01">詳細を見る</Link>
```

```tsx
<Link to="/product/p01">詳細を見る</Link>
//    ↑
//    └─ 移動先の URL（href ではなく to）
```

`href` ではなく **`to`** を使うのがポイントです。見た目は普通のリンクですが、クリックしてもリロードは起きません。

## NavLink：今いるページを目立たせる {#navlink}

ナビの「今いるページ」を目立たせたいときは、`<Link>` の代わりに **`NavLink`** を使います。`NavLink` は「今このリンク先にいるか（`isActive`）」を教えてくれるので、それでクラスを切り替えます。

```tsx
import { NavLink } from 'react-router-dom'

<NavLink
  to="/favorites"
  className={({ isActive }) => (isActive ? styles.active : styles.link)}
>
  お気に入り
</NavLink>
```

`className` に**関数**を渡せて、その引数の `isActive` が `true` なら `styles.active` を当てます。今いるページのリンクだけ色が変わる、あの動きです。

## わざと壊す：Link の代わりに `<a>` を使う {#break}

違いを体感します。商品一覧のリンクを、`<Link>` ではなく `<a>` で書いてみます。

```tsx title="わざと a タグにする"
<a href="/product/p01">詳細を見る</a>
```

クリックすると、画面が**一瞬白くなって**から読み込み直されます（ページ全体のリロード）。もし何か state を持っていたら、それも消えます。`<Link to="/product/p01">` に戻すと、白い点滅は消え、中身だけがスッと差し替わります。**SPA の中のリンクは `<Link>`**——これが理由です。

## 書き方カタログ：Link と NavLink {#catalog}

```tsx
// ふつうの移動
<Link to="/">一覧へ</Link>
<Link to={`/product/${product.id}`}>詳細</Link>

// 今いるページを目立たせる
<NavLink to="/favorites" className={({ isActive }) => (isActive ? styles.active : styles.link)}>
  お気に入り
</NavLink>
```

## うまくいかないとき {#trouble}

- **クリックで画面が白く点滅する** … `<a href>` を使っています。`<Link to>` に変えます。
- **`to` が効かない** … `<Link href>` になっていませんか。`<Link>` は `href` ではなく `to` です。
- **外部サイトへのリンク** … 別サイト（`https://...`）への移動は、逆に普通の `<a href>` でよいです。`<Link>` はアプリ内の移動用です。
