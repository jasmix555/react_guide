## リンク以外で移動したいとき {#why}

`<Link>` は「押したら移動」です。でも、「**何か処理をしたあとで**移動したい」ことがあります。たとえば「カートに入れる → 完了したらカート画面へ」。このクリック＝即移動ではない移動には、**`useNavigate`** を使います。

```tsx
import { useNavigate } from 'react-router-dom'

function AddButton() {
  const navigate = useNavigate()

  function handleClick() {
    // ...カートに入れる処理...
    navigate('/cart') // 処理のあとで移動
  }

  return <button onClick={handleClick}>カートに入れて進む</button>
}
```

```tsx
const navigate = useNavigate()
navigate('/cart')
//       ↑
//       └─ 移動先の URL。<Link> の to と同じ考え方
```

`useNavigate()` で `navigate` 関数を受け取り、好きなタイミングで `navigate('/行き先')` を呼びます。

## 一つ戻る {#back}

数値を渡すと履歴を移動できます。`navigate(-1)` は「ブラウザの戻る」と同じです。

```tsx
navigate(-1) // 一つ前のページへ戻る
```

「詳細ページの『戻る』ボタン」などに使えます。

## 404：どの URL にも一致しないとき {#notfound}

存在しない URL（`/prodcut/p01` のような打ち間違い）を開かれたとき、真っ白ではなく「見つかりません」を出したい。**`path: '*'`** は「他のどれにも一致しなかった全部」に一致する特別なルートです。一番最後に置きます。

```tsx
children: [
  { index: true, element: <ProductListPage /> },
  { path: 'product/:id', element: <ProductDetailPage /> },
  { path: 'favorites', element: <FavoritesPage /> },
  { path: '*', element: <NotFoundPage /> }, // 上のどれにも一致しない URL
]
```

`NotFoundPage` には、一覧へ戻るリンクを置くと親切です。

```tsx title="src/pages/NotFoundPage.tsx"
import { Link } from 'react-router-dom'

export function NotFoundPage() {
  return (
    <div>
      <h1>ページが見つかりません</h1>
      <Link to="/">一覧へ戻る</Link>
    </div>
  )
}
```

## わざと壊す：navigate を呼ぶのを忘れる {#break}

`useNavigate` は「関数を受け取るだけ」です。受け取っただけで**呼ばなければ、何も起きません**。

```tsx
const navigate = useNavigate()

function handleClick() {
  // ...処理...
  navigate // ← 呼んでいない（() が無い）
}
```

`navigate` と書くだけでは関数を指しているだけで、移動しません。`navigate('/cart')` のように **`()` を付けて呼ぶ**必要があります（[関数を値として渡す](/guide/javascript/functions-as-values)と同じ話です）。

## 書き方カタログ：Link と useNavigate {#catalog}

```tsx
// クリックで即移動 → Link
<Link to="/favorites">お気に入り</Link>

// 処理のあとで移動 → useNavigate
const navigate = useNavigate()
navigate('/cart') // 指定した URL へ
navigate(-1) // 一つ戻る
```

## うちの標準 {#standard}

<Std
  decision="ユーザーがクリックして移動するものはすべて Link。useNavigate は「送信成功の結果として移動する」ような場面に限る"
  alt="ページが描画される前に必ず走らせたいリダイレクト——認証ガードなど——は、コンポーネントのエフェクトではなく loader やルート単位のチェックに置きます。"
>

この原則は「どちらが便利か」ではなく「ユーザーが何を得るか」の話です。`Link` は本物のアンカーを描画するので、中クリックでき、別タブで開け、コピーでき、読み上げソフトにもリンクとして伝わります。`<div>` の `onClick` の中で `useNavigate` を呼ぶ形は、そのどれも提供しません。「別タブで開きたい」と思われる可能性が少しでもあるなら、それは `Link` でなければなりません。

</Std>

## うまくいかないとき {#trouble}

- **`navigate` を呼んでも移動しない** … `navigate('/x')` と `()` を付けて呼んでいるか確認します。
- **404 が出ない** … `{ path: '*' }` のルートを登録しているか、一番最後に置いているかを確認します。
