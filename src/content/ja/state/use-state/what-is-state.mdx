## まず結論：普通の変数では画面は変わらない {#why}

React で一番最初につまずくのがここです。**普通の変数を書き換えても、画面は変わりません。** これは仕様であって、バグではありません。

React の画面は「**コンポーネント関数が返した JSX**」でできています。React は、**特別な合図があったときだけ**その関数をもう一度呼んで、画面を描き直します。普通の変数を `let count = 0` として書き換えても、その「合図」が出ないので、React は「描き直す必要がある」と気づけません。

その合図を出すのが、**state** です。次のコードで、両者を並べて確かめます。

## コードで見る：ただの変数 vs state {#code}

`src/components/PlainVsState/PlainVsState.tsx` を新規作成して、**この全文**を貼り付けてください。左が「ただの変数」、右が「state」です。

```tsx title="src/components/PlainVsState/PlainVsState.tsx（新規作成・全文）"
import { useState } from 'react'

export function PlainVsState() {
  let plain = 0 // ❌ ただの変数
  const [count, setCount] = useState(0) // ✅ state（次のページで詳しく分解します）

  return (
    <div>
      <p>ただの変数：{plain}</p>
      <button
        type="button"
        onClick={() => {
          plain = plain + 1
          console.log('plain =', plain)
        }}
      >
        ＋1（変わらない）
      </button>

      <p>state：{count}</p>
      <button type="button" onClick={() => setCount(count + 1)}>
        ＋1（変わる）
      </button>
    </div>
  )
}
```

違いは 1 か所だけです。左は `let plain = 0` の**ただの変数**を `plain = plain + 1` で書き換えています。右は `useState` の **state** を `setCount` で更新しています（`useState` の中身は次のページで 1 つずつ分解します。ここは「state だと動く」を体感するのが目的です）。

## 保存すると何が起きるか {#result}

左の「＋1」を何回押しても、画面は **`0` のまま**です。右の「＋1」は、押すたびに増えます。同じ「＋1」なのに結果がまるで違います。

さらに、左を押しながら**ブラウザのコンソール（`F12`）**を見てください。`plain = 1`、`= 2`…と、**値そのものは増えている**のが分かります。つまり、**変数の中では増えているのに、画面が描き直されないから見えないだけ**なのです。ここが core の理解です。

## なぜこういう仕組みなのか {#model}

もし変数を書き換えるたびに画面を描き直していたら、いつ・何をきっかけに更新すべきか React には分かりません。**「state が変わったときだけ描き直す」と決めておく**ことで、React は無駄なく・正確に画面を更新できます。

<JsNote feature="コンポーネントは「何度も呼ばれる関数」">

これまで関数は「呼ばれたら 1 回動く」ものでした。コンポーネント関数は違い、**state が変わるたびに何度も呼び直され**ます。呼び直されるたびに、その時点の state の値で JSX を作り直す——この「作り直し」を **再描画（re-render）** と呼びます。

</JsNote>

  hint="コンソールには 1〜5 と増えて出ますが、画面の数字は変わりません。"

コンソールには `plain = 1` から `= 5` まで順に出ます。でも画面の数字は **`0` のまま**です。**「値は変わっているのに、画面に反映されない」**——これが「普通の変数では画面が変わらない」の正体です。画面を動かしたいなら state が要る、と体で覚えてください。

</Together>

## うちの標準 {#standard}

<Std
  decision="画面の表示と連動して変わる値は、必ず state で持つ"
  alt="表示に一切関係しない一時的な計算用の値（ループのカウンタなど）は、普通の変数で構いません。画面に出る・画面を変える値だけを state にします。"
>

「この値、変わったら画面も変わってほしい？」——答えが「はい」なら state。普通の変数は「画面と関係ない計算」にだけ使います。まずこの線引きができると、この先がぐっと楽になります。

</Std>

## うまくいかないとき {#trouble}

- **値を変えたのに画面が変わらない** … 普通の変数を書き換えていませんか。state（`useState`）にします。
- **コンソールでは正しいのに画面が古い** … まさに再描画が起きていない状態です。更新は state の更新関数で行います。

<SummaryBox>

- 普通の変数を書き換えても、React は再描画しない（画面は変わらない）
- state を更新すると、React はコンポーネントを呼び直し、画面を描き直す
- 画面と連動する値は state で持つ。それ以外は普通の変数でよい

</SummaryBox>
