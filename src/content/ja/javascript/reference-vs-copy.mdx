<LearnBox>

- 数値・文字列は「コピー」される（別物になる）
- 配列・オブジェクトは「共有」される（同じものを指す）
- 「コピーしたつもりが、元まで変わる」バグと、その直し方

</LearnBox>

## なぜこのページが一番バグを防ぐのか {#why}

「変数 B に A を入れて、B だけ書き換えたはずなのに、A まで変わっていた」——これは、経験者でも週に一度は踏むバグです。原因は、JavaScript が値の種類によって**扱い方を変えている**ことにあります。ここを理解すると、React の「なぜ毎回新しいオブジェクトを作るのか」も腑に落ちます。少し抽象的ですが、手を動かせば必ず分かります。

## 2 種類の値がある {#two-kinds}

JavaScript の値は、大きく 2 種類に分かれます。

- **プリミティブ**：数値・文字列・真偽値・`null`・`undefined`。**中身そのもの**を持ち運びます。
- **オブジェクト**：オブジェクト `{}` と配列 `[]`。**中身の「置き場所（住所）」**を持ち運びます。

この「中身そのもの」か「住所」かの違いが、コピーの結果を分けます。

## プリミティブはコピーされる {#primitive}

数値や文字列を別の変数に入れると、**中身がまるごと複製**されます。片方を変えても、もう片方は無関係です。

```js
let a = 100
let b = a // 100 がコピーされる
b = 200

console.log(a) // 100（a はそのまま）
console.log(b) // 200
```

`b` を `200` にしても、`a` は `100` のままです。数値は「中身そのもの」を持つので、`b` はまったくの別物になりました。ここは直感どおりです。

## オブジェクトは共有される {#object}

問題はこちらです。オブジェクトや配列を別の変数に入れても、**中身は複製されません**。両方が**同じ 1 つの中身を指す**だけです。

```js
const a = { price: 100 }
const b = a // 「同じ置き場所の住所」がコピーされる（中身は 1 つ）

b.price = 200

console.log(a.price) // 200  ← a も変わってしまう！
```

「共有」と「コピー」を、部品に分けて見比べます。

```js
const b = a
//    ↑   ↑
//    │   └─ a が配列/オブジェクトなら「中身の住所」を渡すだけ（共有）
//    └─ b は a と同じ 1 つの中身を指す

const b = { ...a }
//    ↑   ↑
//    │   └─ ... で中身を広げた「新しい箱」を作る
//    └─ b は独立したコピー。書き換えても a に影響しない
```

- **`const b = a`**（`a` がオブジェクト/配列）… **共有**。同じ中身を指すだけ。片方を書き換えると両方変わる
- **`const b = { ...a }` / `[...a]`** … **コピー**。中身を広げた別の箱。独立している
- プリミティブ（数値・文字列）は `const b = a` でも中身が複製される（共有は起きない）

`b.price` を変えたのに、`a.price` まで `200` になりました。`const b = a` は、中身を複製したのではなく、**同じオブジェクトの住所**を `b` にも渡しただけだからです。`a` と `b` は、同じ 1 つの箱を別の名前で指しています。

<Callout type="analogy">

プリミティブは「紙に書いた数字をコピーして渡す」——相手が書き換えても自分の紙は無事です。オブジェクトは「1 冊のノートの**置き場所**を教える」——相手も自分も同じノートを見ているので、どちらが書き込んでも両方に反映されます。

</Callout>

<JsNote feature="参照 = 中身の住所">

`const b = a`（`a` がオブジェクト）のとき、`b` に入るのは中身ではなく「中身がある場所の住所」です。これを**参照**と呼びます。`a` と `b` は同じ住所を指しているので、どちらから書き換えても同じ中身が変わります。

</JsNote>

## わざと壊す：コピーしたつもりで元が変わる {#break-shared}

実際のバグの形で見ておきましょう。「元の商品を残して、値引き版を作る」つもりのコードです。

```js
const original = { name: 'トマト', price: 100 }

const sale = original // コピーしたつもり
sale.price = 80

console.log(sale.price) // 80
console.log(original.price) // 80  ← 元まで値引きされた！
```

`sale` だけ値引きしたかったのに、`original` まで `80` になりました。エラーは出ません。`sale` と `original` が同じ箱を指していたからです。これが「コピーしたつもり」バグです。

## 直し方：新しい箱を作る {#fix}

本当にコピーしたいときは、スプレッドのページでやった `{...}` や `[...]` で、**中身を広げた新しい箱**を作ります。

```js
const original = { name: 'トマト', price: 100 }

const sale = { ...original } // 中身を広げた「別の箱」
sale.price = 80

console.log(sale.price) // 80
console.log(original.price) // 100  ← 元は無事！
```

`{ ...original }` は、`original` の中身を新しいオブジェクトに広げ直します。`sale` は別の箱になったので、書き換えても `original` に影響しません。配列なら `[...original]` です。**「オブジェクトや配列を安全にコピーしたい」＝スプレッドで新しく作る**、と結びつけてください。

<Callout type="warn">

`const b = a`（`a` がオブジェクト・配列）は、コピーではなく**共有**です。片方を書き換えると両方変わります。独立したコピーが欲しいときは `{...a}` / `[...a]` で新しく作ります。

</Callout>

## React とのつながり {#react}

React が「state を更新するときは新しいオブジェクト・配列を作れ」と言うのは、この仕組みが理由です。同じ箱の中身を書き換えても、箱（住所）は同じままなので、React は「変わっていない」と判断して画面を更新しません。`{...}` や `[...]` で**別の箱**を渡して初めて、「別物になった＝描き直そう」と気づきます。詳しくは state のパートでやりますが、根っこはこのページです。

<Together
  task="配列 a = [1, 2, 3] を b にそのまま入れて b.push(4) したとき、a はどうなるか予想してから、コンソールで確かめてください。次に、a を壊さずに 4 を足した新しい配列を作ってみましょう。"
  hint="const b = a は共有。独立させるなら const b = [...a]。"
>

```js
const a = [1, 2, 3]
const b = a
b.push(4)
console.log(a) // [1, 2, 3, 4]  ← a も変わる（共有だから）

// 壊さずに足す：新しい配列を作る
const a2 = [1, 2, 3]
const b2 = [...a2, 4]
console.log(a2) // [1, 2, 3]（無事）
console.log(b2) // [1, 2, 3, 4]
```

`const b = a` は同じ配列を指すので、`b.push(4)` が `a` にも反映されます。`[...a2, 4]` なら新しい配列になり、`a2` は無傷です。

</Together>

## もっと知りたい人へ {#deeper}

<Deeper title="浅いコピー：入れ子の中身までは複製されない">

`{...original}` は**一番外側だけ**を新しくします（浅いコピー）。中に入れ子のオブジェクトがあると、その入れ子は**まだ共有**されたままです。

```js
const a = { name: 'トマト', detail: { stock: 10 } }
const b = { ...a }
b.detail.stock = 0
console.log(a.detail.stock) // 0  ← 入れ子は共有されている
```

普段のうちの標準では、state を「入れ子だらけ」にせず浅く保つので、これで困る場面は多くありません。深い複製が必要になったら、その階層も個別に `{...}` するか、専用のライブラリを検討します（今は「浅いコピーという言葉がある」だけ覚えておけば十分です）。

</Deeper>

## 書き方カタログ：コピーの書き方 {#catalog}

オブジェクトや配列を「元を残して変えたい」ときは、必ず新しい箱を作ります。よく使う形を並べます。

```js
const b = a                           // 共有（a がオブジェクト/配列なら要注意）
const obj2 = { ...obj }               // オブジェクトを浅くコピー
const arr2 = [...arr]                 // 配列を浅くコピー
const next = [...arr, x]              // コピーしつつ末尾に追加
const updated = { ...obj, price: 80 } // コピーしつつ一部を上書き
const n2 = n                          // 数値はそのままで独立（コピーされる）
```

`const b = a` だけが「共有」で、あとは新しい箱を作る「コピー」です。React の state 更新も、この「新しく作る」が土台になります。

## うちの標準 {#standard}

<Std
  decision="オブジェクト・配列を「変えたいけど元は残したい」ときは、必ず {...} / [...] で新しく作ってから変える"
  alt="意図的に「同じものを指したい」場面（同じ設定を複数箇所で参照するなど）は共有で構いません。区別して使えることが大事です。"
>

`const b = a`（オブジェクト・配列）は共有だと知っておき、独立したコピーが欲しいときは `{...a}` / `[...a]`。この 1 点を守るだけで、「コピーしたつもりで元が壊れる」バグと、React の「更新したのに画面が変わらない」バグの両方を、まとめて防げます。

</Std>

## うまくいかないとき {#trouble}

- **片方だけ変えたのに、もう片方も変わる** … `const b = a` で共有しています。`{...a}` / `[...a]` で新しく作ってから変えます。
- **`{...}` でコピーしたのに、入れ子だけ元も変わる** … 浅いコピーだからです。その入れ子も個別に新しくします（深掘り参照）。

## まとめと練習 {#summary}

<Exercise answer="数値なので b は独立したコピーになり、a は 10 のまま。プリミティブ（数値・文字列・真偽値）は中身がコピーされるので、共有バグは起きません。共有が起きるのはオブジェクトと配列だけです。">

`let a = 10; let b = a; b = 99` としたとき、`a` はいくつでしょう。なぜオブジェクトのときと結果が違うのかも説明してみてください。

</Exercise>

<SummaryBox>

- プリミティブ（数値・文字列・真偽値）はコピーされる。片方を変えても他方は無関係
- オブジェクト・配列は共有される（同じ住所を指す）。片方を書き換えると両方変わる
- 独立したコピーが欲しいときは `{...obj}` / `[...arr]` で新しい箱を作る。React が新しい入れ物を求めるのもこの理由

</SummaryBox>
