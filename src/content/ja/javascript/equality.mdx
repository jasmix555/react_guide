## まず結論：`===` を使う {#use-strict}

値が等しいか調べる記号は 2 つあります。**`===`（厳密等価）を使い、`==` は使いません**。理由は、`==` が「型が違っても、勝手に型を合わせてから比べる」ため、予想外の結果になるからです。

```js
1 === 1 // true
1 === '1' // false（数値と文字列。型が違うので違う）
1 == '1' // true（== は型を合わせてしまう）
```

`===` は「型も値も同じか」を、素直に比べます。`!==` はその否定（等しくない）です。

## `==` が起こす、意外な true {#loose-traps}

`==` が型を合わせることで、直感に反する結果がいくつも生まれます。コンソールで確かめてください。

```js
0 == '' // true（どちらも 0 扱い）
0 == false // true
'' == false // true
null == undefined // true（この 2 つだけの特別ルール）
```

これらは全部、`===` なら `false` です。**「なぜか条件が合ってしまう」バグの温床**なので、`==` は避けます。

<Callout type="mistake" title="== は使わない、が安全策">

`==` の型変換ルールを全部覚える必要はありません。**いつも `===`（と `!==`）を使う**、とだけ決めておけば、この手のバグはまず起きません。

</Callout>

## NaN は自分自身とも等しくない {#nan}

数値にならない計算の結果は `NaN`（Not a Number）です。この `NaN` には特殊な性質があります。**`NaN` は、自分自身と比べても `false`** になります。

```js
const n = Number('あいう') // NaN（数値にできなかった）

n === NaN // false（！）
Number.isNaN(n) // true（NaN 判定はこれを使う）
```

「NaN かどうか」は `=== NaN` では調べられません。**`Number.isNaN(値)`** を使います。

## オブジェクトは「実体」で比べる {#identity}

数値や文字列は「中身」で比べますが、**オブジェクトや配列は「同じ実体か（同じ箱か）」で比べます**。中身が同じでも、別々に作った箱は等しくありません。

```js
{ a: 1 } === { a: 1 } // false（中身は同じでも別の箱）
[1, 2] === [1, 2] // false（同上）

const x = { a: 1 }
const y = x
x === y // true（y は x と同じ箱を指している）
```

この「中身ではなく実体で比べる」感覚は、次の[参照とコピー](/guide/javascript/reference-vs-copy)につながります。いまは「オブジェクト同士の `===` は、中身の一致ではない」とだけ押さえてください。

## 書き方カタログ：等価の要点 {#catalog}

```js
1 === 1 // true（型も値も同じ）
1 === '1' // false（型が違う）
a !== b // 等しくない
Number.isNaN(x) // NaN 判定はこれ（=== NaN は使えない）
obj1 === obj2 // オブジェクトは「同じ実体か」を見る
```

## うまくいかないとき {#trouble}

- **条件が意図せず成立する** … `==` を使っていませんか。`===` に変えると多くが直ります。
- **`x === NaN` がいつも false** … NaN は自分とも等しくありません。`Number.isNaN(x)` を使います。
