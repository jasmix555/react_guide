<LearnBox>

- 関数は数値や文字列と同じ「値」で、持ち運べる
- 関数を別の関数に**渡す**（コールバック）
- 「渡す（名前だけ）」と「呼ぶ（`()` を付ける）」の決定的な違い

</LearnBox>

## なぜこれが一番大事なのか {#why}

React では、ボタンに「押されたらこの処理をして」と**関数そのものを渡します**。`onClick={handleClick}` のような書き方です。ここで「関数を渡す」と「関数を呼ぶ」を取り違えると、**押してもいないのに勝手に動く**、あるいは**押しても動かない**という、初心者が必ず一度はハマるバグになります。

そのバグを二度と踏まないために、このページだけは特にゆっくり進めます。出発点は「**関数も値である**」という 1 点です。

## 関数は値：変数に入れられる {#value}

数値を変数に入れられるように、**関数も変数に入れられます**。実はアロー関数のページで、もうやっていました。

```js
const greet = () => {
  console.log('こんにちは')
}

console.log(typeof greet) // 'function'
```

`greet` という変数の中身は「関数」です。`typeof` で確かめると `'function'` と出ます。つまり関数は、`100` や `'トマト'` と同じように、**名前を付けて持ち運べる値**なのです。ここを飲み込めれば、この後は素直に理解できます。

## 呼ぶには () を付ける {#call}

変数に入れた関数を**実行（呼び出し）**するには、名前の後ろに `()` を付けます。

```js
const greet = () => console.log('こんにちは')

greet // これは「関数そのもの」を指しているだけ。実行されない
greet() // これで初めて実行される → こんにちは
```

`greet` は「関数という値」を指しているだけで、**何も起きません**。`greet()` と `()` を付けて初めて、中の処理が動きます。**`()` が「今すぐ実行して」の合図**です。この違いが、次のすべての土台になります。

React ではこの違いが `onClick` にそのまま出ます。2 つを部品に分けて見比べます。

```tsx
onClick={fn}
//       ↑
//       └─ 名前だけ＝関数そのものを渡す。押されたときに実行される（○）

onClick={fn()}
//       ↑ ↑
//       │ └─ () は「今すぐ実行して」の合図
//       └─ 描画された瞬間に fn() が走り、戻り値が渡ってしまう（✗）
```

- **`onClick={fn}`** … 名前だけ。「この関数を、押されたときに呼んで」と**渡す**（○）
- **`onClick={fn()}`** … `()` 付き。**その場で実行**し、戻り値を渡す。描画の瞬間に走る（✗）
- 引数を渡したいときは `onClick={() => fn(arg)}` と**包む**

<JsNote feature="名前だけ＝関数そのもの、() 付き＝実行した結果">

`greet` と書くと「関数そのもの（まだ動いていない）」を指します。`greet()` と書くと「関数を実行して、その**結果**」を指します。渡したいのが「処理そのもの」なのか「処理した結果」なのかで、`()` を付けるかどうかが変わります。

</JsNote>

## 関数を別の関数に渡す（コールバック） {#callback}

関数は値なので、**別の関数に引数として渡せます**。渡された側は、好きなタイミングでそれを呼び出します。これを**コールバック**と呼びます。`setTimeout`（時間差で実行する道具）で見てみましょう。

```js
const sayHi = () => console.log('やあ')

setTimeout(sayHi, 1000) // 1秒後に sayHi を呼んでね、と渡す
```

`setTimeout` に `sayHi` を**名前だけ**（`()` を付けずに）渡しています。「この関数を、1 秒後に**あなたが**呼んで」という意味です。`map` や `filter` にコールバックを渡していたのも、まったく同じ仕組みでした。

## わざと壊す：渡すつもりで呼んでしまう {#break-call-vs-pass}

ここが本題です。`sayHi` に**うっかり `()` を付けて**渡すと、まるで違う動きになります。見比べてください。

```js
const sayHi = () => console.log('やあ')

// ① 渡す：名前だけ
setTimeout(sayHi, 1000)
// → 1秒後に「やあ」。正しい。

// ② 呼ぶ：() を付けてしまった
setTimeout(sayHi(), 1000)
// → 今すぐ「やあ」が出て、1秒待たない。
```

②では、`sayHi()` が**その場で実行**され、コンソールに「やあ」が即座に出ます。そして `sayHi()` の**戻り値（`undefined`）**が `setTimeout` に渡ってしまい、1 秒後には何も起きません。「時間差で動かしたかったのに、すぐ動いて、しかも 2 回目は動かない」という、意図と正反対の結果です。

React に置き換えると、これはこうなります。

```jsx
<button onClick={handleClick}>  // ○ 押されたときに呼んでね（関数を渡す）
<button onClick={handleClick()}> // ✗ 描画した瞬間に実行してしまう（結果を渡す）
```

`onClick={handleClick()}` と書くと、ボタンが**画面に出た瞬間に** `handleClick` が走ってしまいます。「押してないのに動く」「無限に再描画される」といった不具合の、代表的な原因です。**渡すときは名前だけ。`()` は付けない**——これを体に入れてください。

<Callout type="warn">

`onClick={...}` などに関数を渡すときは、**`()` を付けない**のが基本です。「押してもいないのに動く」「ページを開いた瞬間に処理が走る」ときは、まず `()` を付けてしまっていないかを疑ってください。

</Callout>

## 引数を渡したいときは、包む {#wrap}

「でも `handleClick` に引数を渡したい」——そのときは、`()` を付けて直接呼ぶのではなく、**その呼び出しを別の関数で包みます**。

```js
const remove = (id) => console.log(`${id} を削除`)

// ✗ これはその場で実行されてしまう
// onClick={remove(5)}

// ○ 「押されたら remove(5) を呼ぶ関数」を渡す
// onClick={() => remove(5)}
```

`() => remove(5)` は「実行されたら `remove(5)` を呼ぶ、新しい関数」です。これを渡せば、**押されたときに初めて** `remove(5)` が動きます。引数を渡したいときはこの「包む」形、と覚えておくと、React で毎日使います。

<Together
  task="コンソールで、'完了' と出す関数 done を作り、setTimeout で「2秒後に」実行させてみてください。そのあと、わざと () を付けて即実行になってしまう様子も確認しましょう。"
  hint="setTimeout(done, 2000) が正しい形。setTimeout(done(), 2000) にすると即実行になります。"
>

```js
const done = () => console.log('完了')

setTimeout(done, 2000) // 2秒後に「完了」（正しい）

setTimeout(done(), 2000) // すぐ「完了」が出て、2秒後は何も起きない
```

`done` は名前だけ渡すと「2 秒後に呼んで」という意味になります。`done()` と `()` を付けると、その場で実行され、戻り値 `undefined` が `setTimeout` に渡ってしまいます。渡すのは「処理そのもの」——名前だけ、です。

</Together>

## 書き方カタログ：関数の渡し方 {#catalog}

「渡す＝名前だけ」「`()`＝今すぐ実行」。ハンドラには名前だけ、引数が要るときだけ `() =>` で包みます。

```tsx
onClick={handleClick}       // ○ 名前だけ渡す（押されたら呼ばれる）
onClick={() => remove(id)}  // ○ 引数を渡す → () => で包む
onClick={() => setCount(0)} // ○ その場の処理も包んで渡す
setTimeout(sayHi, 1000)     // ○ コールバックも名前だけ渡す
onClick={handleClick()}     // ✗ 描画の瞬間に実行してしまう
onClick={remove(id)}        // ✗ これも即実行（戻り値が渡ってしまう）
```

上の 4 つが「渡す」、下の 2 つが「呼ぶ（即実行）」です。`()` が付いているかどうかだけで、動きが正反対になります。

## うちの標準 {#standard}

<Std
  decision="ハンドラに関数を渡すときは名前だけ。引数が要るときだけ () => で包む"
  alt="包む関数が毎回作られるのが実測で問題になる、という高度な場面では useCallback を検討します（Part 9）。まずは () => で包む形で問題ありません。"
>

`onClick={fn}` が基本形。引数を渡したいときだけ `onClick={() => fn(arg)}`。`onClick={fn()}` や `onClick={fn(arg)}` は「その場で実行」なので、ハンドラには渡しません。「渡す＝名前だけ」「`()`＝今すぐ実行」を区別できれば、React のイベント処理でつまずきません。

</Std>

## うまくいかないとき {#trouble}

- **ページを開いた瞬間に処理が走る／押してないのに動く** … `onClick={fn()}` のように `()` を付けて渡しています。名前だけにするか、`() => fn(arg)` で包みます。
- **押しても何も起きない** … 逆に関数を渡せていない（名前を間違えている、`{}` で囲んでいない）可能性があります。渡している名前を確認します。
