<PartIntro>

ここまで、商品データは `products.json` を**直接 import** していました。手元にファイルがあるので一瞬で読めます。でも実際のアプリでは、データは**サーバーにあって、通信して取ってくる**のがふつうです。通信は時間がかかり、失敗することもあります。このパートは、その現実に向き合います。

手元の `my-shop` は、ルーティングまで済んだ状態です。

```
my-shop/src/
├─ main.tsx                       ← ルーター
├─ pages/                         ← 一覧・詳細・お気に入り
├─ types/product.ts               ← Product 型
└─ data/products.json             ← いまは直 import
```

</PartIntro>

## 完成形を先に見る {#goal}

通信には**時間**がかかり、**失敗**もします。だから画面は「読み込み中」「失敗」「成功」の 3 つを出し分けます。下のボタンで、その 3 状態を体験してください。

<Demo title="読み込み中・失敗・成功の 3 状態">
  <FetchDemo />
</Demo>

「成功で読み込む」を押すと、少し待って一覧が出ます（その間は「読み込み中」）。「失敗させる」を押すと、エラー表示になります。**この 3 状態を自分で扱えるようにする**のが、このパートのゴールです。

## なぜ「データ取得」を 1 つのパートにするのか {#why}

`import products from './products.json'` は、**必ず一瞬で成功**します。だから「読み込み中」も「失敗」もありません。でも `fetch` は違います。

- **時間がかかる** … 押してすぐには返ってこない。その間、何を見せる？
- **失敗する** … 電波が悪い、サーバーが落ちている。そのとき、何を見せる？

この「待つ」「失敗する」を扱えないと、通信するアプリは作れません。逆に、**loading / error / success の 3 状態**さえ押さえれば、たいていのデータ取得は同じ形で書けます。それをこのパートで身につけます。

## このパートの進み方 {#roadmap}

1. **直 import から fetch へ** — なぜ、いつ通信に変えるのか。
2. **fetch の基本** — `async` / `await` と `.json()`。
3. **useEffect で取得する** — 「画面が出たら 1 回取る」を書く。
4. **3 つの状態** — 読み込み中・失敗・成功を state で持つ。
5. **取得データに型を付ける** — 返ってきた JSON を `Product[]` にする。
6. **カスタムフックに切り出す** — `useProducts()` にまとめて使い回す。

各ページに**コード全文**と練習を用意しています。通信の「待ち」と「失敗」を、実際に手を動かして確かめてください。
