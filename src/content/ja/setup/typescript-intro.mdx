バリアントで「TypeScript」を選びました。ここでは**「型があると何が嬉しいか」だけ**に絞って話します。書き方の詳細は、後半の「React のための TypeScript」パートでみっちりやるので、今は雰囲気を掴めば十分です。

## TypeScript とは {#what}

**TypeScript は、JavaScript に「型」を足した言語**です。ふつうの JavaScript に、「この値は文字列」「この値は数値」という注釈を書けるようにしたもの、と思ってください。書いたコードは最終的にただの JavaScript に変換されて動くので、**JavaScript の上位互換**です。

一番のご利益は、**間違いを「実行する前」に教えてくれる**ことです。

## 型が無いと、こういう事故が起きる {#accident}

LP 制作でも身に覚えがあるはずです。共通パーツに渡す変数の名前を、途中で `title` から `heading` に変えた。1 か所は直したけれど、**別の 3 か所で古い名前のまま**になっていた。ブラウザで見ると、その 3 か所だけ文字が消えている——けれどエラーは出ない。どこで消えたのか、目で探すしかない。

JavaScript は、存在しない名前を読んでも**黙って `undefined` を返す**ので、こういう「静かなバグ」が起きます。動かしてみるまで気づけません。

## 型があると、赤い線で止めてくれる {#help}

TypeScript なら、名前を変えた瞬間に、古い名前を使っている残り 3 か所すべてに**赤い波線**が付きます。実行する前に、エディタが「ここ、その名前もう無いよ」と教えてくれるのです。

## わざと壊す：文字列の関数に数値を渡すと赤い線が出る {#break-wrong-type}

型が守ってくれる様子を、小さな例で体感します。文字列を受け取る関数に、わざと数値を渡してみます。

```ts title="型の効き目"
function greet(name: string) {
  return `こんにちは、${name} さん`
}

greet(123) // ← 文字列のはずが数値
```

`greet(123)` の `123` に、エディタが赤い波線を引き、こう教えてくれます。

```
Argument of type 'number' is not assignable to parameter of type 'string'.
```

「`number` 型の引数は `string` 型のところには渡せません」という意味です。**実行する前に**間違いが分かる——これが型のいちばんの価値です。`123` を `'佐藤'` に直せば、波線は消えます。

## なぜ最初から TypeScript なのか {#why-ts}

「まず JavaScript で慣れてから TypeScript へ」という順番もありますが、このガイドは**最初から TypeScript**でいきます。私たちがこれを学ぶ理由は、最終的に「チームでレビューできる、壊れにくいコード」を書けるようになることだからです。先に型なしの書き方を体に入れてしまうと、あとで直すのが大変です。だから最初から、型と一緒に覚えます。
