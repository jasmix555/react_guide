# 学ぶページの品質基準（チェックリスト）

react_guide の「学ぶ」タブの各ページが満たすべき基準。**新しいページを書くとき・既存を直すときは、これを上から順に確認する。**

対象読者は **React 未経験・JavaScript も浅い** LP 制作者。ゴールは「読んで理解する」ではなく **「自分で書けるようになる」**。だから **コードが主役**であって、動くデモはその補助にすぎない。

---

## 最重要の原則：デモはコードの「追加」であって「代わり」ではない

クリックできるが読めないデモは、この読者にとってほぼ無価値。**React が動くこと**は誰も疑っていない。読者が知りたいのは **どう書くか**。コードを隠す・断片で見せる・文章で説明で済ませる、をやめる。

## コード可視性ルール（必須）

1. **完全なファイルを最低1つ** — 断片ではなく、パス付きでコピペすれば動く**ファイル全文**（import・型・export まで）。`useState` を扱うページには、`useState` を使った完全なコンポーネントファイルが載っていること。ファイルの fence には必ず実パス： ` ```tsx title="src/components/…/X.tsx" ` 。

2. **コード → 結果の説明 → 動くデモ、の順**（デモだけで済ませない・デモを先に出さない）。ページの並びは必ず：**書くコード（全文）→ 保存すると何が起きるか（文章）→ 実際の動き（`<Demo>`）**。「完成形を先にデモで見せる」は禁止。動機づけしたいなら文章一行で「このページで作るもの」を述べ、デモは対応するコードの**後**に置く。

3. **`<DemoSource>` は学ぶページでは開いた状態が既定**（コンポーネント側で `open` 既定 true 済み）。レシピページだけ `open={false}` で畳んでよい。

4. **新しい構文には必ず「構文の分解」** — 使う前に、部品ひとつひとつに矢印とコメントで名前を付ける図を出す。例：

   ```tsx
   const [count, setCount] = useState(0);
   //     ↑      ↑                  ↑
   //     │      │                  └─ 初期値。最初に入っている値
   //     │      └─ 更新する関数。これを呼ぶと再描画される
   //     └─ いまの値。読み取り専用だと思ってよい
   ```

   そのあと一行「なぜ配列か（Part 2 の配列の分割代入。名前を自分で決められるから）」。対象：`useState`・`useEffect(fn, deps)`・`onClick={fn}`・`{...prev, key: value}`・JSX を返す `map`・引数リストでの props 分割代入・`?:` と `&&`、など **新規に出る構文すべて**。

5. **概念ページには「書き方カタログ」** — 「例は分かった」と「自分で書ける」の間を埋めるため、同じ概念を数パターンで並べた短い一覧をページ末尾近くに置く。例（useState）：

   ```tsx
   const [count, setCount] = useState(0);          // 数値
   const [name, setName] = useState('');           // 文字列
   const [isOpen, setIsOpen] = useState(false);    // 真偽値
   const [items, setItems] = useState<string[]>([]); // 配列
   const [form, setForm] = useState({ name: '', email: '' }); // オブジェクト
   const [product, setProduct] = useState<Product | null>(null); // まだ無い（型は Part 6）
   ```

   `useEffect`（マウント時だけ／値が変わったとき／クリーンアップあり）、イベントハンドラ（引数なし／引数あり／イベントオブジェクト）、条件表示（`?:`／`&&`）にも同様に。

6. **「〜と書きます／追加します」の直後には必ずコードブロック** — 文章がコードを説明したら、例外なくすぐ下にそのコードを見せる。文章でコードの代わりにしない。

## 従来の密度規約（引き続き有効）

- 各ページ：なぜ →（詳しく手を動かす手順）→ **わざと壊す（再現エラー全文）** → ❌/✅（Diff）→ うちの標準（Std）→ うまくいかないとき → まとめ → 練習（Exercise）。
- 概念直後に **`<Together>`（一緒にやってみよう）** をページ中盤に 1–2 個（ヒント＋答え全文の折りたたみ）。読むだけにさせない。
- 見出しは「中身」を表す（「ステップ n」「わざと壊してみる」単独禁止 → 内容を書く）。slug も内容に。
- 例は必ず読者自身のプロジェクト（`my-shop`）の実パス。
- 未習の概念を出すときは前方リンク＋「あとで詳しくやります」。
- MDX 落とし穴：JSX 属性（`<Together task="…">` 等）に生の `"` / `\"` 不可（内側は `'…'`）。frontmatter `description` に ` : `（空白コロン空白、`? :` 含む）は YAML を壊すのでクォート。見出しに生 `{ }` 不可。表セル内の `|` はエスケープ／言い換え。
- 各パート末に `npm run check`（lint + lint:content + tsc + build + contrast）を通す。
